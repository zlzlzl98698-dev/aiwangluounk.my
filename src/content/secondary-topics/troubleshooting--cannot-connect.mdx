“客户端明明已经点亮了连接开关，测速也全是 30ms–60ms 的绿色低延迟，可一打开 Chrome 或 Edge 浏览器访问外网，页面还是转半天圈，最后弹出 `ERR_PROXY_CONNECTION_FAILED`、`ERR_CONNECTION_TIMED_OUT` 或干脆提示未连接到互联网。”——这是桌面端代理故障中**迷惑性最强、最容易让新手怀疑人生**的场景。

之所以会出现“客户端里面一片绿、浏览器外面一片红”的割裂感，根本原因在于两者的通信链路完全不同：**客户端的节点测速，是由代理内核直接向外发包**，根本不需要经过浏览器扩展、系统代理注册表、PAC 脚本或浏览器 DNS；而**浏览器想要把一个网页请求送出国门，必须顺畅穿过六道关卡**：浏览器扩展控制权 → 浏览器内置 DoH/DNS 行为 → 操作系统代理/PAC 或 TUN 虚拟网卡 → 本地监听端口 → 客户端代理模式与节点选择 → 机场网关鉴权与带宽限额。

本 SOP 将彻底拆解这条接管链上的全部断点，带你通过 1 分钟双视图定界，逐层扫除浏览器扩展劫持、内置 DoH 绕过、工作空间 PAC 覆盖、全局误选 `DIRECT` 以及套餐封号限速阈值等五大隐蔽陷阱。

## 一、黄金 60 秒定位法：先看 `Connections` 与 `Logs` 定责分叉

发现测速绿色但网页打不开时，**严禁直接卸载软件、乱改系统高级设置或盲目切换上十个节点**。打开你的主力客户端（以 **Clash Verge Rev**、**FlClash** 或 **v2rayN** 为例），同时盯紧界面左侧的两个诊断面板：**`Connections`（连接）** 与 **`Logs`（日志）**，然后回浏览器刷新一次目标海外网页。

根据面板里有没有出现这条新请求，问题瞬间一分为二：

| `Connections` 连接面板观测结果 | `Logs` 日志面板典型表现 | 故障定责结论 | 优先跳转排障章节 |
| :--- | :--- | :--- | :--- |
| **分叉 A：连接列表一片空白**，完全看不到刚才刷新的网页域名 | 没有相关出站报错，或启动时出现 `bind: address already in use` | **流量压根没进代理内核**！浏览器请求直接走本地直连，或撞上了被占用的死端口 | 进入 **第二节**（扩展/安全软件/端口）与 **第四节**（PAC 覆盖） |
| **分叉 B：连接列表有新增域名记录**，且右侧规则/节点列显示 **`DIRECT`** | 正常记录 `match ... using DIRECT` | **流量进了内核，但被你手动或规则直连了**！常见于 `Global` 误选 `DIRECT` 或模式切错 | 进入 **第五节**（Global 模式误选 `DIRECT`）与 **第三节**（DoH 绕过分流） |
| **分叉 C：连接列表有记录且走了海外节点**，但上传/下载字节数极小或瞬间断开 | 刷出 `EOF`、`timeout`、`connection reset` 或加载卡在几 KB | **流量成功发向机场，但在出站或账号网关被截断**！需核对套餐状态、限速或单节点假绿 | 进入 **第六节**（封号/限速阈值与备胎路由） |

记住这张三分定界表：只要学会看 `Connections`，你就再也不用在“到底是浏览器坏了还是机场坏了”之间瞎猜。

## 二、排查系统代理被 Chrome/Edge 扩展或安全软件劫持（分叉 A 首查）

当 `Connections` 列表一片空白时，首要怀疑对象不是机场，而是**浏览器层与操作系统层的代理控制权争夺战**。

### 2.1 浏览器代理扩展残留劫持（Proxy SwitchyOmega / ZeroOmega 等）

在 Chrome 与 Edge 浏览器架构中，**浏览器扩展通过 `chrome.proxy` 接口接管代理的优先级，高于 Windows 和 macOS 的操作系统代理设置**。许多用户几年前装过 `Proxy SwitchyOmega`、`ZeroOmega`，或者装了某些“网页加速/比价/爬虫抓包/学术访问助手”插件，哪怕后来几乎忘了它的存在，甚至以为已经停用，它依然在后台死死锁住浏览器的代理出口：

- **典型症状**：浏览器地址栏右侧的代理插件图标灰色显示或停在「直接连接（Direct）」、或者指向一个早已被你改掉的旧端口号（如以前用过 `7890`，现在 Clash Verge Rev 默认用 `7897`）；或者在「浏览器设置 → 系统 → 打开计算机的代理设置」页面顶部，直接弹出一行灰色提示：**“某扩展程序正在控制此设置”**。
- **排障处理步骤**：
  1. 在地址栏输入 `chrome://extensions/`（Chrome）或 `edge://extensions/`（Edge），逐一检查所有已启用的扩展。
  2. 如果你保留了 SwitchyOmega / ZeroOmega，点击浏览器右上角扩展图标，将其情景模式明确切换为**「系统代理（System Proxy）」**，或者专门为你当前客户端的真实混合端口（如 `127.0.0.1:7897`）新建一个匹配情景模式。
  3. 如果该扩展不再需要，建议直接在扩展管理页面**关闭开关或移除**，随后完全关闭浏览器全部窗口（包括任务管理器里残留的浏览器后台进程）重新打开，观察代理控制权提示是否消失。

### 2.2 本地监听端口被安全软件或同类工具抢占（端口冲突）

另一种导致测速绿灯却连不上代理的高发故障，是**客户端图形外壳亮着「系统代理」，但底层内核实际上没抢到监听端口**。

例如 Clash 系经典端口 `7890` / `7897`，以及 v2rayN 常用端口 `10808` / `10809`。当你电脑上同时运行了另一款代理软件、曾经未彻底退出的僵尸核心进程、网易 UU / 雷神等游戏加速器、或者本地开发调试工具（如 Charles、Fiddler、特定本地 API 服务）时，新的核心启动后会因为端口已被占用而报错 **`bind: address already in use`**。此时系统代理指向 `127.0.0.1:7897`，而实际监听在 `7897` 上的是另一个毫无转发能力的程序，浏览器自然报错 `ERR_PROXY_CONNECTION_FAILED`。

**只读核查与无损修复动作**：
1. 打开客户端的 `Logs` 检查启动前几行有没有端口绑定失败的红色提示，或在 Windows 管理员 PowerShell 中执行只读端口占查命令：
   ```powershell
   # 以 Clash Verge Rev 常见默认端口 7897 或 7890 为例，查询占用进程的 PID
   netstat -ano | findstr ":7897"
   tasklist /FI "PID eq 查到的数字PID"
   ```
2. 确认无用冲突进程后退出它；或者更彻底地，进入代理客户端设置，将 **Mixed Port（混合端口）** 修改为一个冷门高位端口（如 `17897`），保存后重启内核，再**先关闭再重新打开一次「系统代理」开关**，让操作系统刷新写入新的端口号。

### 2.3 安全软件防火墙拦截与“代理开关假亮”核查

1. **Windows Defender / 第三方安全卫士拦截**：如果安全软件曾弹窗拦截核心二进制文件（`mihomo.exe`、`xray.exe`、`sing-box.exe`）的出站或本地回环监听权限，图形界面上的系统代理开关虽然亮着，请求一进入端口就会被防火墙悄悄丢弃。请核对 Windows 安全中心「允许应用通过防火墙」列表，确保核心程序在当前网络类型（专用/公用）下获得放行（注意：仅放行经官方 SHA-256 校验的正版程序，切勿放行来路不明的下载站修改版，核验方法见 [客户端无法启动与安全校验 SOP](/troubleshooting/app-startup/)）。
2. **确认系统代理地址与客户端是否真正一致**：打开 Windows「设置 → 网络和 Internet → 代理 → 手动设置代理」，或 macOS「系统设置 → 网络 → 代理」，肉眼核对里面的 IP 是否为 `127.0.0.1`、端口是否与客户端设置页面里显示的混合端口分毫不差。
3. **浏览器正常但部分桌面软件 / 终端 / UWP 断网的补充提醒**：如果你发现 Chrome 能上网，但 PowerShell、VS Code、`git` 或微软商店提示无网络，这是因为它们默认不遵循操作系统 HTTP 代理（Windows UWP 应用默认被沙盒禁止访问 `127.0.0.1`）。此时请参考 [系统代理 vs TUN 虚拟网卡深度对比](/guides/articles/tun-vs-system-proxy-dns/)，按需启用 UWP 回环豁免或关闭系统代理切入 **TUN 模式**。

## 三、排查浏览器强制开启内置 DoH（安全 DNS）绕过代理

如果浏览器扩展已清空、系统代理端口完全正确，但打开某些海外网页依然卡在“正在解析主机”或规则分流彻底失灵，请立刻检查一个极其隐蔽的浏览器设置：**内置加密 DNS（DNS over HTTPS，简称 DoH）**。

### 3.1 浏览器内置 DoH 是如何架空代理客户端的？

在现代代理客户端（特别是开启了 **Fake-IP** 模式或精细域名分流规则的 Mihomo / sing-box 客户端）中，系统工作的前提是：**浏览器的域名解析请求必须先经过代理客户端内置的 DNS 模块**。只有拿到了你要访问的域名（比如 `claude.ai` 或 `github.com`），规则引擎才能准确判断它该走代理节点还是直连，并在 Fake-IP 模式下立刻给出一个 `198.18.x.x` 虚拟映射地址交给底层转发。

然而，Chrome、Edge 与 Firefox 近年来纷纷内置并强推「使用安全 DNS（DoH）」功能：
- 当你手动开启了「使用自定义安全 DNS 提供商（例如填入了某个公共 DoH 服务）」，或者浏览器自动升级到了强制 DoH，**浏览器会直接在应用内部跳过操作系统网络栈，自己向远端加密解析域名 IP**。
- 在**系统代理模式下**，这可能导致浏览器绕过规则分流把错误解析出的海外真实 IP 扔出直连，或者在部分无法直连境外公共 DoH 的本地宽带下，**浏览器连 DNS 查询本身都直接超时卡死**，页面表现为始终无法打开且 `Connections` 里看不到对应海外域名记录（或者只看到一堆直连失败的裸 IP）。
- 在 **TUN 模式下**，虽然三层网卡能拦住 IP 数据包，但因为缺失了客户端 DNS 阶段记录的原始域名映射，所有的 `DOMAIN-SUFFIX`、`GEOSITE` 规则都会瞬间退化成只能靠 GeoIP 猜，极易引发分流错乱与网页半截卡死。

### 3.2 关闭 / 还原浏览器安全 DNS 的对照排查步骤

1. **Chrome 浏览器**：进入右上角三点菜单 →「设置」→「隐私和安全」→「安全」→ 向下滚动找到**「使用安全 DNS」**。
2. **Edge 浏览器**：进入设置 →「隐私、搜索和服务」→ 向下滚动到「安全性」板块 → 找到**「使用安全 DNS 指定如何查找网站的网络地址」**。
3. **测试验证做法**：暂时将「使用安全 DNS」开关**关闭**（或切回「使用当前服务提供商」并关闭自定义 DoH URL），彻底重启浏览器后再次访问刚才打不开的海外网页。如果网页瞬间秒开且客户端 `Connections` 列表立刻恢复清晰的域名分流记录，就证明是浏览器内置 DoH 绕过了代理 DNS（更多关于 Fake-IP 与 DNS 分流的排障细节见 [DNS 错误排查 SOP](/troubleshooting/dns/)）。

## 四、排查工作空间、公司内网与校园网强制 PAC 脚本覆盖

在办公电脑、公司内网工作空间（Workspace）或高校校园网环境下，还有一类让人防不胜防的断联现象：**代理客户端刚点亮“系统代理”，网页能打开几秒钟，随后突然全部失灵**；或者打开系统网络设置，发现「手动设置代理」的开关不知何时被灰掉了，而上方的**「使用设置脚本（PAC）」**正处于开启状态。

### 4.1 强制 PAC 覆盖的工作原理与识别特征

企业 IT 部门或校园网为了统一审计上网流量、分配内网业务系统出口，常常通过以下机制强制接管系统代理：
- **Windows 域控组策略（GPO）或终端安全管理软件**：每隔几分钟自动向注册表下发一次强制代理策略，写入公司内部的 `http://.../proxy.pac` 自动配置脚本地址，并把手动代理关闭或灰化锁定。
- **WPAD 自动检测代理冲突**：部分路由器或内网网关开启了 `使用自动配置脚本` 配合 `自动检测设置`，系统会优先向内网 DHCP/DNS 查询 `wpad` 配置，一旦命中内网脚本，优先级同样会直接压过手动输入的 `127.0.0.1` 代理地址。
- **企业零信任 VPN 客户端冲突**：如终端运行着办公专用的零信任接入软件或沙盒工作空间，这类工具常会在内核驱动或系统代理层不断刷新自身路由表，与个人代理软件互斥。

### 4.2 合规核查与安全边界处理

> **重要合规与安全提示**：如果你使用的是**公司配发的受控办公电脑**或处于明确限制外部网络策略的工作空间，**切勿使用任何强行修改系统策略、注入驱动或绕过企业安全管控的越权操作**，以免违反单位信息安全管理规定或破坏正常办公内网连接。

对于**个人自有电脑**回家后依然残留了曾经填过的 PAC 脚本，或不小心误触了自动设置脚本的用户，按以下安全步骤无损检查清理：
1. **Windows 核查路径**：打开「设置 → 网络和 Internet → 代理」：
   - 查看第一项「自动检测设置」：若非必须建议暂时关闭测试；
   - 查看第二项**「使用设置脚本」**：检查是否开启并填入了陌生的 `.pac` 地址。如果确认是以前装过的旧工具残留（非当前单位必用内网配置），记录下原脚本地址备忘后将其关闭，再重新打开下方代理客户端写入的「手动代理服务器（`127.0.0.1:端口`）」。
2. **macOS 核查路径**：打开「系统设置 → 网络 → 当前 Wi-Fi 或以太网 → 详细信息 → 代理」，确认**「自动代理配置（PAC）」**和「自动发现代理」未处于误勾选状态。
3. **区分便携环境**：如果你确定本地系统代理持续被工作空间锁定，而个人设备在允许的前提下需要独立验证网络，可以核对是否误连了自带认证/PAC 的访客 Wi-Fi，优先切换回手机 `5G` 热点或纯个人家用宽带确认节点本身是否正常。

## 五、排查客户端开启「全局（Global）」模式却把 `DIRECT` 选为当前节点

这一条看起来极其不可思议，但却是实际支持工单中**排名极高的“低级却高频”真故障**。

### 5.1 为什么“我明明开了全局模式，却完全没走代理”？

很多用户从朋友或网帖听说：“遇到海外网站打不开或者规则分流不对时，切到 **Global（全局）模式** 最稳！”于是他打开 Clash Verge Rev、FlClash、Shadowrocket 或 Stash，在代理模式顶栏果断点击切换到了 **`Global（全局）`**，然后满心欢喜地回去刷网页——结果发现不仅还是打不开外网，去查 IP 归属地显示的依然是本地国内宽带地址！

点开客户端的 `Connections` 面板一看，所有网页请求赫然全标着 **`DIRECT`**。原因就出在 Mihomo / Clash 架构的底层默认逻辑上：

1. 在 **`Rule（规则）`** 模式下，常见海外域名会去匹配你选好的「节点选择 / Proxy」策略组（里面选的是香港、日本或新加坡节点）。
2. 一旦你把顶部模式切到 **`Global（全局）`**，客户端就会**放弃使用所有规则组**，改为把 100% 的流量一股脑塞进一个名叫 **`GLOBAL`** 的内置总分组里。
3. 而在绝大多数机场自动生成的 YAML 配置文件里，这个 `GLOBAL` 分组排在第一顺位、且默认高亮选中的出站项，恰恰不是你的海外节点，而是系统内置的 **`DIRECT`（直连）**，甚至有些配置默认排在第一位的是 **`REJECT`（拦截丢弃）**！
4. 如果你只按了 `Global` 切换开关，却没有点开 `GLOBAL` 策略组卡片手动选中一个具体的海外节点（比如香港 01 或日本 02），客户端就会忠实地把你的“全局流量”全部通过 `DIRECT` 原地直连出去——表面上看软件开着、节点测速也全绿，实际上**零字节流量经过代理节点**！

### 5.2 两分钟完成模式与出站节点双核查

除了误选 `DIRECT`，还有一种情况是手滑点到了模式栏里的 **`Direct（直连）`** 模式（部分客户端主界面有 `Rule` / `Global` / `Direct` 三个并列按钮）。请按以下顺序逐项确认：

1. **检查顶部主运行模式**：日常上网请保持在 **`Rule（规则）`** 模式，确保未误触切换到 `Direct（直连）`。
2. **如果确实需要临时开 `Global（全局）` 排障**：切换过去后，务必在「代理（Proxies）」页面找到置顶的 **`GLOBAL`** 分组将其展开，确认里面当前蓝色/绿色高亮选中的是**具体可用的海外节点名称**（或有效的节点选择组），**绝对不能停留在 `DIRECT` 或 `REJECT` 上**。
3. **在 `Rule` 模式下也要查各策略组当前选中项**：比如你为 AI 单独建了策略组、或者主节点选择组里默认是 `自动选择`，点进去确认当前实际落地的子节点没有误选成 `DIRECT`。在 Shadowrocket（小火箭）中，则是检查首页的「全局路由」选项——如果误设成了「直连（Direct）」，无论下面选了哪个节点，所有流量都不会走代理，须切回「配置（Config）」或「代理（Proxy）」。

## 六、排查套餐实际处于封号、流量耗尽或限速阈值（含公告与备胎路由）

如果经过前面四步排查，你在 `Connections` 面板里清清楚楚地看到浏览器流量已经进入了正确的海外节点（既不是空白、也不是 `DIRECT`、也没有 DoH 绕过），但网页依然转圈超时、或者加载完半个标题就彻底卡死不动——这时就要怀疑最后一道关口：**你的机场账号当前虽然还没把测速缓存踢掉，但在服务端网关实际上已经处于封号、停机或极端限速阈值**。

### 6.1 为什么被限速或停用时，测速列表依然可能显示有延迟？

许多用户百思不得其解：“明明刚才测速还是 `35ms` 绿色，怎么可能被封号或限速？”这里面存在三种常见的技术与运营机制：
1. **延迟缓存未失效**：测速面板显示的是 5 分钟前缓存的延迟结果，而你的包月流量刚好在刚才因为多倍扣费（如 `2x`/`3x` 高倍率看视频）耗尽清零，后端网关切断了实际数据转发通道，只有刷新测速或直接进网页才会暴露。
2. **极低带宽限速阈值（“假在线、真卡死”）**：部分品牌针对特定节点过载或套餐触发公平使用规则时，并不会直接切断连接，而是把单账号带宽压到极低阈值（类似于站内 [光速云](/brands/guangsuyun/) `2026-08-19` 珠海联通测试样本中观测到「美国 02 节点异常低至 `1.6KB/s`」的状态）。在这种速率下，轻量级几百字节的 `204` 测速包依然能勉强通过并算出一个绿色毫秒数，但动辄几 MB 的现代网页资源和脚本在浏览器里根本拉不下来，最终全部超时报错。
3. **账号触发并发或审计规则被临时封停**：例如同时在过多不同 IP 设备上在线、或者订阅链接意外泄露到公共网络引发异地大流量并发，后端防火墙会将该账号 UUID 临时拉黑，表现为测速时通时断或转发直接被重置 `EOF`。

### 6.2 机场公告核查与备胎路由应急切换路径

当怀疑命中账户停用、限速或线路区域性故障时，请按照以下标准化核查与应急止损路径处理：

1. **登录机场官方用户面板核对三项核心状态**（若主域打不开请用手机 `5G` 或核对官方发布页，警惕仿冒站见 [官网识别与防钓鱼审计](/brands/official-sites/)）：
   - **当前有效天数与剩余流量**：重点检查是否因为节点倍率提前耗尽了当月配额（关于倍率扣费见 [线路倍率规则](/routes/multiplier/)）；
   - **当前在线设备数与并发警告**：查看是否出现异常陌生 IP 占用，疑似订阅泄露立刻点击重置订阅链接；
   - **官网公告栏 / 官方通知频道**：核查是否正在进行节点割接、特定地区维护或临时限速调整（这是区分正常维护与异常停运的必备依据，详见 [停运与跑路核查准则](/risks/shutdowns/)）。
2. **单节点限速 vs 全线故障验证（备胎节点切换）**：
   - 先在同一机场订阅里手动切换至不同国家、不同编号的冷门节点（例如从拥堵的港 `01` 切到冷门港 `18` 或日/新节点）；
   - 若机场支持多协议切换（如 [一翻云](/brands/yifan/) 提供 `Hysteria 2`、`VLESS-Reality` 与 `Shadowsocks`），从当前拥堵或被限速协议切至另一协议测试网页下载表现。
3. **启动事先预备的“备胎路由方案”**：
   - 在跨境办公或高频使用 AI 工具（如 ChatGPT、Claude、Gemini）的场景下，单靠单一节点池永远存在单点失效或晚高峰触及限速阈值的风险。最稳健的架构是**“主力月付机场 + 百元级一次性不限时备用包”双线配置**：
   - 当主力线路突发区域性维护、限速阈值或域名切换故障时，无需在急着交稿或开会时焦头烂额地到处找新机场，直接在 Clash Verge Rev 或 Shadowrocket 里切入备用机场节点顶上即可（低门槛备用包核算可参考 [不限时机场一次性流量包专题](/pricing/non-expiring/)）。
   - 如果确认原服务商长期高频率限速、公告停更失联或限制过多，则可对照 [风险应对与替代方案指引](/risks/alternatives/)，按“是否需要通用订阅、预算区间及 AI/流媒体需求”精准挑选月付替代品进行平滑迁移，切忌病急乱投医盲目冲高价年付。

## 七、无损验证闭环：恢复连通后的五项验收检查

完成上述任一环节的修复后，请顺手跑一遍这五个验证动作，确保不是短暂假通或留有隐患：

1. **查看 `Connections` 实时流量走线**：打开一个未缓存过的海外测试网页，确认 `Connections` 中出现该域名、右侧匹配为你期望的代理策略组与出站节点（而非 `DIRECT`），且上下行字节数持续正常跳动。
2. **核对出口 IP 与地区一致性**：确认浏览器访问显示的出口地区与所选节点一致（无意中未关闭其他代理扩展或遗留 PAC）。
3. **测试关闭代理后直连是否完整恢复**：正常点关闭「系统代理 / TUN」并退出一次客户端，打开国内常用网站，确认没有残留代理地址或 Fake-IP 缓存导致关掉软件就断网（若遇到关代理断网，参见 [TUN 与系统代理残留修复](/troubleshooting/tun-proxy/)）。
4. **确保单一接管模式运行**：确认没有同时开启「系统代理」与「TUN 模式」或并存两套本地代理软件，避免日后休眠唤醒再度引发端口互抢或路由环路。
5. **留存备份**：将调试通顺的 Profile 与覆写设置顺手备份一份，把故障现象与最终定位点简单记下，下次遇到同类提示 `30` 秒内即可照方抓药解决。
