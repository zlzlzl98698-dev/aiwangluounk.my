很多用户在第一次安装或更新代理客户端时，连节点列表的影子都还没看到，软件就在第一步直接“罢工”：Windows 上双击图标半天没反应、界面弹出一个纯白或纯黑的空框、刚点开关就报错核心进程丢失；macOS 上则直接弹出令人不安的“软件已损坏，无法打开，你应该将它移到废纸篓”；Android 手机上刚更新完机场专属 App，一打开就闪退回桌面。

面对启动故障，最危险、也最容易把小问题拖成大麻烦的做法就是**“百度搜索第三方网盘重打包绿色版”**或者**“直接关闭全部系统杀毒并强制删光安装目录”**。这不仅极易中招窃取订阅的木马程序，还会把之前辛苦整理的规则与本地订阅记录全部抹平。事实上，无论是开源桌面端（如 `Clash Verge Rev`、`v2rayN`、`FlClash`、`Hiddify`）还是移动端工具，启动与内核初始化阶段依赖的底层条件高度规律化。下面将按系统环境逐一拆解故障机理，给出可逆、带安全校验的无损修复步骤。

> **排障前第一铁律：先保配置、先验哈希，再动文件**
> 在删除任何文件夹、回退版本或向安全软件添加白名单前，务必完成两件事：第一，如果之前已经导入过订阅或编写过覆写规则，先去系统数据目录把整份配置文件夹复制备份到桌面；第二，任何准备还原或放行的二进制文件（`.exe` / `.dmg` / `.apk`），必须确认出自开源项目官方发布页或品牌正规渠道，并完成 SHA-256 指纹核验——**绝不给来源不明的第三方破解包或网盘搬运包加白放行**。

## 一、Windows 常见启动障碍：WebView2 白屏、`.NET` 缺失与核心丢包

Windows 桌面上主流的开源代理客户端虽然都长着图形界面，但底层渲染框架与核心运行依赖截然不同。把这几条依赖线理顺，就能在 30 秒内分清为什么软件打不开。

### 1. Clash Verge Rev 白屏 / 黑屏 / 界面卡死：排查 Microsoft Edge WebView2 Runtime

以 **Clash Verge Rev** 为代表的现代桌面客户端（以及同类采用 Tauri 等轻量 Web 容器技术构建的客户端）为了控制安装包体积与跨平台一致性，**本身不再内置数百 MB 的 Chromium 浏览器内核**，而是直接调用 Windows 操作系统底层安装的 **Microsoft Edge WebView2 Runtime** 来渲染窗口界面（基础选型对比参见 [Windows 代理客户端全矩阵](/guides/articles/windows-clients-guide/)）。

当出现以下症状时，几乎可以确诊为 WebView2 运行环境异常：
- 双击图标后窗口边框弹出来了，但内部一片纯白或纯黑，既没有菜单栏也没有报错提示；
- 任务栏或系统托盘能看到软件图标甚至核心已经在后台运行，但主窗口点开永远是空白或无法响应鼠标点击；
- 弹出英文或中文提示，明确包含 `WebView2`、`msedgewebview2.exe` 初始化失败或缺失字样。

**为什么正常电脑会缺 WebView2？**
Windows 11 默认预装了该组件，但许多精简版 Windows 10、LTSC 企业长效支持版、老旧系统升级后未自动更新的版本，或者用户此前使用过所谓的“彻底卸载 Edge / 系统极致优化清理工具”误删了共享运行库，都会导致 WebView2 缺失或注册表指向残缺。此外，部分双显卡笔记本（核显与独显切换异常）或老旧显卡驱动下，WebView2 默认开启的 GPU 硬件加速也会造成窗口渲染白屏。

**无损修复四步操作**：
1. **核对系统是否已安装**：打开 Windows「设置」→「应用」→「安装的应用」（Windows 10 为「应用和功能」），在列表搜索 `WebView2`。如果完全搜索不到，或者版本号异常陈旧、提示损坏，就需要重新补齐。
2. **从微软官方源补装 Evergreen 独立安装程序**：前往微软开发者官网获取 **WebView2 Runtime Evergreen Bootstrapper 或 Standalone Installer（匹配 x64 或 arm64）**，以正常权限运行安装。安装过程不会强行把你的默认浏览器改成 Edge，也无需重启卸载已有软件，安装完成后再重启代理客户端测试。
3. **检查用户目录写入权限与锁死进程**：若系统明明有 WebView2 却依旧白屏，打开任务管理器结束所有残留的客户端进程与卡死的 `msedgewebview2.exe` 子进程；同时检查该客户端是否被强行放进了只读受保护目录，或以不同权限账号混合启动过（例如上次用管理员身份启动，这次用普通用户启动，导致 `WebView2` 缓存目录权限锁死）。
4. **验证图形兼容与多账户权限**：更新本地显卡驱动，或者避免养成“每次都右键以管理员身份强行运行 GUI 主界面”的习惯——在 Clash Verge Rev 中，涉及虚拟网卡权限的操作应当通过内置的 `Service Mode` 完成，主界面保持普通用户权限启动才最稳妥，详见 [Clash Verge Rev 深度指南](/clients/clash-verge-rev/)。

### 2. v2rayN 双击无反应闪退或报“核心丢失”：`.NET Desktop Runtime` 与整合包区分

与 Clash Verge Rev 的 Web 容器路线不同，经典多核心调度软件 **v2rayN** 在 Windows 上基于 `.NET` 桌面框架开发（详情见 [v2rayN 多核心调度指南](/clients/v2rayn/)）。它的启动障碍集中在两个极其典型的误区上：

- **误区一：系统缺少对应版本的 `.NET Desktop Runtime`（导致双击直接闪退、甚至毫无弹窗）**
  新版 v2rayN 依赖微软较新的 **.NET 8 Desktop Runtime**（具体版本随客户端大版本演进，需核对发布页说明）。如果系统只装了普通控制台运行库而没装 **Desktop Runtime（包含 Windows 桌面窗口支撑）**，或者大版本不匹配，双击 `v2rayN.exe` 往往在任务管理器闪现一秒后直接消失。解决方式是按照开源发布页注明的运行时要求，从微软官方补装匹配 `x64` 或 `arm64` 架构的 `.NET Desktop Runtime`。
- **误区二：下载了不含核心的“纯界面精简包”，或安装目录缺乏写入权限**
  必须牢记：**v2rayN 只是一个调度外壳**，真正执行协议加解密和转发的，是它同目录下 `bin` 文件夹里的 `xray.exe`、`sing-box.exe` 或 `mihomo.exe`。开源发布页通常会同时放出体积较小的纯外壳包与包含全部核心的 **`With-Core`（或自包含运行库）整合包**。如果你误下了纯外壳包，软件界面虽然能打开，但一旦测试延迟或启动代理，日志会立刻报错找不到对应 core 可执行文件。新手务必下载官方 `With-Core` 完整压缩包，并在下载后核对 SHA-256。

### 3. 切勿在压缩包预览窗口直接双击运行，以及路径避坑

另一类令新手百思不得其解的闪退原因，发生在**完全没解压就双击运行**。使用 WinRAR、7-Zip 或系统内置预览直接打开 `.zip` 后双击里面的 `.exe`，压缩软件只把主程序本身临时解压进 `AppData\Local\Temp` 某个随机子目录。这样运行不仅找不到旁边的核心二进制文件与依赖库，关闭窗口后临时目录被清理，全部配置与节点记录也会瞬间蒸发！

此外，请遵守两条路径规范：
- **使用纯英文无空格路径**：例如解压至独立目录（如 `D:\Tools\ProxyClient\`），避开包含中文字符、全角括号或 `#`、`&`、`!` 等特殊符号的路径（部分底层内核命令行参数传递时会对特殊字符解析失败）。
- **避开系统只读目录**：便携免安装版（Portable）切勿直接扔进 `C:\Program Files\` 下运行！Windows 启用了 UAC 保护，普通权限程序无权向 `Program Files` 内部写入配置文件、日志和更新后的核心，必然触发配置保存失败或启动闪退。

## 二、安全软件误杀内核（`mihomo.exe` / `xray.exe` / `sing-box.exe`）校验与加白

“昨天还好好的，今天一开电脑软件就打不开代理了，点开关没任何反应，或者日志红字报错 `Access is denied` / 找不到核心文件。”——在 Windows 上，**90% 的无故核心进程丢失都是 Windows Defender 或第三方安全软件静默隔离所致**。

### 1. 为什么开源代理内核极易触发启发式误报？

底层代理核心（如 `mihomo.exe`、`xray.exe`、`sing-box.exe`）在技术特征上包含高度加密网络通信、监听本地多端口、修改代理路由以及通过 TUN 驱动直接拦截三层数据包等行为。在安全软件的启发式行为扫描引擎看来，这些特征与部分恶意远控木马非常相似。尤其是刚升级到最新发布的客户端或测试版（Alpha）内核时，新编译的二进制文件尚未在安全云端积累足够多的白名单信誉度，极易被实时防护在后台无声拖进隔离区。

### 2. 安全第一：加白前必须完成的验明正身步骤

需要极度警惕的是：**市场上确实存在大量被黑灰产挂马、篡改了内核的“假安装包”或“破解绿色版”！** 如果你从搜索引擎竞价广告或陌生小站下载的安装包被杀毒软件报警，**它大概率真的带毒，绝对不能盲目放行**。

执行加白前，必须先按以下顺序验证清白：

1. **确认来源渠道**：安装包是否亲手下载自开源项目的正规官方发布页面（注意站内 [全平台客户端安装规范](/guides/install/) 强调：在未完成在线验证前不轻信任何第三方网盘或搬运站）。
2. **用 PowerShell 比对 SHA-256 哈希值**：只要安装包压缩包还在下载目录，打开 PowerShell 运行只读哈希计算，与官方发布页公示的 SHA-256 字符串逐位比对：

```powershell
# 查看下载目录中安装包的 SHA-256 指纹
Get-FileHash -Path "$HOME\Downloads\下载的文件名.zip" -Algorithm SHA256
```

只有**哈希指纹 100% 匹配**，才证明这个文件没有被人二次打包注入恶意代码，属于真正的安全软件“误杀”。

### 3. Windows Defender（Microsoft Defender）精确加白与还原实操

确认文件来源清白后，**切勿全局关闭实时防护**，只需按以下最小范围步骤操作：

1. **打开隔离记录核查是否已被吞掉**：打开「Windows 安全中心」→「病毒和威胁防护」→「保护历史记录」。在记录中查找被拦截的条目，展开详情核对受影响文件路径是否正是你的代理客户端目录（常见文件名：`mihomo.exe`、`xray.exe`、`sing-box.exe` 或 `clash-verge-service.exe`）。
2. **仅添加单一客户端独立目录为排除项（优于单文件加白，避免每次升级内核再被杀）**：
   - 在「病毒和威胁防护」下点击「管理设置」→ 向下滚动找到「排除项」→ 点击「添加或删除排除项」。
   - 点击「添加排除项」→ 选择**「文件夹」** → 仅选中你专门存放代理客户端的单一纯英文子目录（例如 `D:\Tools\ClashVerge\`）。**严禁把整个 `C:\`、`D:\` 或 `Downloads` 下载目录整个加入排除项！**
3. **还原被隔离的内核文件**：回到「保护历史记录」，找到刚才确认无误的核心文件记录，点击「操作」→「还原」；如果此前已经被彻底清除，则重新从刚才校验过 SHA-256 的官方压缩包里把内核解压回这个已加白的目录即可。
4. **第三方杀毒软件处理逻辑同理**：若电脑装有火绒、360 或其他商业杀软，同样应进入其「隔离区 / 信任区」，先核实文件位置再只把该独立子目录加入信任白名单，同时保留全局防护与浏览器防护开启。

## 三、macOS、Linux 与服务安装失败：公证隔离、权限锁与配置损坏修复

离开 Windows 之后，macOS 与 Linux 的启动障碍同样有非常明确的触发点。此外，桌面端通用的“服务安装失败”与“配置文件损坏崩溃”也是极其常见的高频故障。

### 1. macOS「已损坏，无法打开」与「无法验证开发者」处理

在 macOS 上下载并拖入「应用程序（Applications）」后双击启动开源客户端（如 Clash Verge Rev、FlClash、v2rayN macOS 版或 SFM），系统经常弹窗拦截：
- 提示 A：**“无法打开 xxx，因为无法验证开发者 / Apple 无法检查其是否包含恶意软件”**
- 提示 B：**“xxx 已损坏，无法打开。你应该将它移到废纸篓。”**

**真实成因**：
第一，Apple 要求所有分发给外部用户的 macOS 应用均需使用付费开发者账号进行签名（Code Signing）和公证（Notarization）。许多免费开源项目没有持续购买苹果开发者证书，下载进系统的 `.dmg` 会被浏览器或下载工具打上 `com.apple.quarantine` 隔离属性，在较新的 macOS（如 Sequoia / Sonoma / Ventura）中就会直接显示为“已损坏”。
第二，另一个常见误区是**硬件架构选错**：在 Apple Silicon（M1/M2/M3/M4）Mac 上下载了没有转译兼容或核心异常的包，或者反向在老款 Intel Mac 上强行运行 `arm64` 专属包，也会直接报损坏或意外退出（参考 [iOS/macOS 客户端架构指南](/guides/articles/ios-macos-clients-guide/)）。

**安全验证与解锁三步法**：
1. **先验证硬件架构与 SHA-256 哈希**：在终端运行命令确认本机芯片与下载镜像一致（`arm64` 对应 M 系列芯片，`x86_64` 对应 Intel）：

```bash
# 确认芯片架构
uname -m

# 核对下载的 dmg 文件 SHA-256 指纹
shasum -a 256 ~/Downloads/客户端安装包.dmg
```

2. **优先使用系统图形化核准（针对“无法验证开发者”）**：打开「系统设置」→「隐私与安全性」，向下滚动到「安全性」区域，点击刚拦截记录旁的**「仍要打开」**并输入管理员密码确认。
3. **移除隔离扩展属性（针对误报“已损坏”）**：若确定安装包哈希与官方一致、架构匹配，但系统仍直接阻断并只给出“移到废纸篓”按钮，可在终端仅对该单一应用程序移除隔离标签：

```bash
# 请将“应用名称.app”替换为应用程序目录中的实际名称，切勿对未知目录批量执行
xattr -cr /Applications/应用名称.app
```

执行后再次双击即可正常启动。切记不要使用关闭全系统 Gatekeeper 的全局放行命令，那会削弱整台 Mac 的基础防护安全线。

### 2. Windows Service Mode 服务安装失败与后台服务卡死

使用 Clash Verge Rev 等桌面客户端时，普通网页代理无需特权，但一旦打算开启虚拟网卡 **TUN 模式**，就必须安装并运行系统服务模式（Service Mode）。常见报错包括点击安装服务后提示安装失败、服务状态一直灰色未激活，或者安装后内核依然起不来。

**排查与修复顺序**：
1. **检查安装路径与账户权限**：确保安装客户端的本地账户属于 Windows 管理员组，点击「Install」弹出 UAC 确认框时务必点「是」。
2. **排查安全软件对服务注册的拦截**：安全软件不仅会杀 `mihomo.exe`，也常在客户端试图向 Windows 服务管理器注册 `clash_verge_service` 时直接静默阻断。按第二节方法核验安全软件拦截记录。
3. **先彻底卸载旧版残余服务再重装**：如果此前覆盖升级过客户端大版本，旧版本残留的服务进程仍在后台锁住二进制文件，就会导致新服务覆盖写入失败。操作方法：先关闭 TUN 开关 → 在服务管理弹窗点击「Uninstall（卸载）」→ 完全退出客户端并在任务管理器确认无残留核心进程 → 重新打开客户端再点击「Install（安装）」。
4. **确认无第二款客户端服务抢占**：如果电脑上同时装了 Clash Verge Rev、Clash Nyanpasu、Hiddify 或 Mihomo Party（注意：站内台账明确提醒 Mihomo Party 须单独核实维护活跃度，不可盲选），不同客户端的后台服务或默认监听端口极易互相踩踏。同一时间只保留并启用一套主力客户端服务。

### 3. 配置文件损坏与覆写脚本写崩导致启动闪退

“昨天还好好的，今天自己改了几行分流规则或者更新了一次订阅，客户端再也打不开了！”——这是导致无故闪退的另一大头号隐形杀手。

**诱因分析**：
- 手动编辑 YAML 配置时不小心混入了 **Tab 制表符**（YAML 严格只允许空格缩进）、缺失冒号后的空格，或者写了不存在的策略组名称引用，导致内核解析瞬间 Panic 崩溃退出；
- 在 Clash Verge Rev 中开启了全局 JavaScript 覆写脚本（Script），而脚本内存在语法错误、空数组异常或者把机场节点全部过滤成空列表，导致客户端一加载配置就闪退；
- 极少数机场后端在模板变更时下发了畸形字符或与当前内核版本不兼容的新字段，更新订阅后直接把软件带崩。

**无损配置备份与回滚步骤**：
不要点击卸载！直接打开配置存储路径，把好端端保留在里面的其他订阅先救出来：
- **Clash Verge Rev 典型配置目录**：
  - Windows：`%APPDATA%\io.github.clash-verge-rev.clash-verge-rev\`（在文件资源管理器地址栏直接输入回车即可直达）
  - macOS：`~/Library/Application Support/io.github.clash-verge-rev.clash-verge-rev/`
  - Linux：`~/.local/share/io.github.clash-verge-rev.clash-verge-rev/`
- **v2rayN 典型配置目录**：便携版通常直接位于解压目录下的 `guiConfigs\` 文件夹内。

**操作顺序**：
1. 先把整个配置目录完整复制一份到桌面作为安全备份。
2. 结束全部残余进程后，把最新修改过的覆写脚本文件（或记录最后激活配置的文件）临时改名移出该目录，让客户端失去错误入口。
3. 重新双击客户端，此时界面会干净启动并恢复空白或默认配置；随后再重新导入订阅，或将备份出来的脚本逐段检查语法后恢复。

### 4. Linux 桌面版 AppImage 与内核能力缺口

在 Ubuntu 22.04/24.04 等现代 Linux 发行版上运行 `.AppImage` 客户端，最常见的一步闪退报错是 `dlopen(): error loading libfuse.so.2` 或沙盒权限阻塞。处理方法：优先选用官方发布的 `.deb` 或 `.rpm` 系统安装包；若必须运行 AppImage，按需补齐 `libfuse2` 依赖库并校验可执行权限（详见 [Linux 与 OpenWrt 客户端指南](/guides/articles/linux-openwrt-clients-guide/)）。需要提醒的是，若内核进程报权限不足无法创建 `tun0` 设备，可通过包管理服务或为内核二进制授予 `CAP_NET_ADMIN` 能力，切忌长期直接用 `sudo` 运行整个图形桌面界面。

## 四、Android `VpnService` 冲突与专属客户端更新后闪退回退策略

移动端的启动与运行故障逻辑与桌面端明显不同。由于系统沙盒约束，Android 端除了面对安装闪退，还高频遭遇**`VpnService` 互斥抢占**以及**机场自研专属 App 更新崩坏**的困境。

### 1. Android 架构错配与 `VpnService` 冲突排障

在 Android 上启动客户端直接闪退或开关弹回关闭，应按以下三项依次排查：

1. **核对 APK 架构（ABI）与来源完整性**：绝大多数近七年的安卓手机为 64 位 ARM（`arm64-v8a`），极老机型为 `armeabi-v7a`（识别命令与细节见 [Android 客户端选型指南](/guides/articles/android-clients-guide/)）。如果强行提取不匹配架构的包或从非官方通道安装了被篡改签名的重打包 APK，启动内核瞬间就会直接闪退。同时再次重申站内安全台账的硬性警示：**切勿从 Google Play 下载已被第三方控制的同名 NekoBox 应用**，日常开源端首选 `v2rayNG`、`FlClash`、`Clash Meta for Android`、`Hiddify` 或 `Karing`。
2. **排查 `VpnService` 单一通道互斥冲突**：Android 系统底层铁律是**同一时间仅允许一个应用激活 `VpnService`**。如果手机正挂着公司办公 VPN、学校内网准入工具、广告拦截软件（依赖本地 VPN 接口过滤的那类）或第二款加速器，启动代理客户端时不仅会被系统直接顶掉，部分专属客户端在系统拒绝移交 `VpnService` 权限甚至缺乏异常捕获时，就会直接闪退。启动前务必先彻底退出其他占用 VPN 通道的应用，并在系统弹窗请求创建 VPN 连接时点击「确定」。
3. **国产 ROM 后台冻结导致的“假闪退”**：MIUI / HyperOS、ColorOS、OriginOS 及 HarmonyOS 会在锁屏或内存紧张时直接清理后台内核进程，用户切换回 App 时表现为软件重新冷启动、节点连接被抹掉。务必按 [安卓 VPN 保活设置](/vpn/android/) 完成电池「无限制/允许后台高耗电」、开启「允许自启动」并在多任务界面锁定卡片。

### 2. 机场专属客户端更新后闪退：安全回退与迁移策略

站内 31 家机场品牌库中，有一大批品牌采用**仅限专属客户端**策略（如 [飞猫云](/brands/feimao/)、[隐形人](/brands/yinxingren/)、[SOGO 云](/brands/sogo/)、[灵猫网络](/brands/lingmao/)、[闪跃](/brands/shanyue/)、[全球云](/brands/quanqiu/)，以及资料标注自 2026 年 10 月起转为专属端模式的 [Firefly](/brands/firefly/) 与存在口径冲突的 [无忧链接](/brands/wuyou/)），另有如 [光速云](/brands/guangsuyun/)、[梯子云](/brands/tiziyun/)、[极连云](/brands/jilian/) 等同时提供自研客户端与第三方通用订阅的“双端兼容”品牌。

由于专属客户端多为闭源定制包装，厂商推送小版本更新时偶尔会出现适配某些 Android 14/15/16 新机型的崩溃 bug，导致**更新后一点开就闪退**。遇到这种情况，请按以下策略冷静止损回退：

1. **先保留账号凭证与本地记录，别盲目直接卸载**：确认自己还记得注册邮箱、密码或备用发布页入口。许多专属客户端卸载重装后本地缓存会被一并抹掉，如果没有保留账号与官网备用地址，连重新登录都要折腾半天。
2. **先尝试仅清缓存（Clear Cache）与关闭私有 DNS**：进入系统「设置 → 应用管理 → 该专属客户端 → 存储」，先点击**「清除缓存」**（注意不要先点清除全部数据），同时检查手机「私人 DNS」是否设为关闭、是否已解除其他 `VpnService` 冲突，然后重开测试。
3. **回退至已验证稳定的上一版本 APK（仅限官方正规渠道保留包）**：如果清除缓存无效，且服务商官网或官方通知频道确认当前新版存在已知闪退问题并给出了历史稳定版本回退包，在核对来源与基本安全扫描后，先彻底卸载坏版本再安装该稳定旧版，并暂时关闭应用内的「启动自动强制更新」弹窗提示。**严禁因为官方新版闪退，就去第三方论坛或陌生网盘下载所谓的“网友修改兼容版专属端”**，那极易导致账号密码与本地隐私被窃取。
4. **双端兼容品牌的终极平替方案——直接切回开源通用客户端**：如果你使用的是兼顾自研端与通用订阅的品牌（例如光速云、梯子云、极连云、光年梯、速界等，完整对比见 [专属端 vs 通用订阅对照](/compare/dedicated-client-vs-universal-sub/)），当自研专属客户端更新频繁闪退、耗电异常或分流僵化时，完全不必苦等厂商修复，直接登录官网面板复制标准通用订阅链接，迁移到更稳定可审计的开源客户端（Android 用 `FlClash` / `Clash Meta for Android` / `v2rayNG`，桌面用 `Clash Verge Rev` / `v2rayN`）即可立即恢复使用，并且彻底告别被单一闭源客户端绑死的风险。

## 五、全平台启动与核心丢失故障速查决策表

在实际排障时，只要对照故障出现的时间节点（双击前、渲染时、拉起核心时、开启 TUN 时）即可 1 分钟对号入座：

| 故障症状 | 所属平台 | 核心根因定位 | 第一优先级无损修复动作 |
| :--- | :--- | :--- | :--- |
| Clash Verge Rev 窗口纯白/纯黑无内容 | Windows | 缺少或损坏 `WebView2 Runtime` / GPU 加速兼容异常 | 安装微软官方 Evergreen 版 WebView2 Runtime 并结束残留进程重启 |
| v2rayN 双击没反应闪退、无任何窗口 | Windows | 缺少 `.NET Desktop Runtime` 或运行库版本不匹配 | 核对发布页要求版本，从微软官方补装匹配架构的 Desktop Runtime |
| 客户端界面能开，点连接报错找不到内核 | Windows | 下载了纯界面包，或核心被杀软静默隔离 | 先查安全中心「保护历史记录」；核验官方压缩包 SHA-256 后为独立英文目录加白并补齐核心 |
| 在压缩包内直接双击，配置不保存且闪退 | Windows | 未完整解压进独立目录，或放进了只读受限目录 | 完整解压至 `D:\Tools\...` 纯英文路径（避开 `Program Files` 与中文符号） |
| macOS 提示“已损坏，移到废纸篓”或无法验证 | macOS | 未公证开源应用携带隔离属性，或架构 `arm64`/`x64` 错配 | `uname -m` 核对芯片并校验 `shasum`，确认官方包无误后隐私核准或终端执行 `xattr -cr` |
| 开启 TUN 时 Service Mode 服务安装失败 | Windows | 拒绝 UAC 授权、杀软拦截服务注册或旧服务进程残留 | 查杀软拦截，关闭 TUN → 点击卸载旧服务 → 清空后台核心进程 → 重新授权安装 |
| 改完规则/脚本或更新订阅后一打开就崩 | 全平台 | YAML Tab 缩进错误、JS 覆写语法错误或订阅异常 | 先备份整个配置文件夹，临时移走刚改的覆写脚本/问题配置重启拉起空白界面后再修复 |
| Android 专属客户端更新后闪退或开关弹回 | Android | APK 架构不匹配、`VpnService` 被占用或新版兼容缺陷 | 关闭冲突 VPN、清除缓存；按需回退官方确认的稳定旧版，双端品牌建议迁往开源客户端 |

把「运行库补齐 → SHA-256 校验后再加白 → 备份配置后排错 → 远离第三方修改包」这四条标准动作固化成习惯，几乎所有客户端启动故障与内核丢失都能在几分钟内安全化解。如果客户端已经能够顺畅启动且核心正常拉起，但后续依然出现全部节点超时、订阅拉取 `200 OK` 返回空白，或开启 TUN 后引发本地开发容器断网，请继续查阅 [节点超时排查树](/troubleshooting/timeout/)、[订阅更新失败排查](/troubleshooting/subscription-failed/) 与 [TUN 与系统代理混合故障](/troubleshooting/tun-proxy/)。
