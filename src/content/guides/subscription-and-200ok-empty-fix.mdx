## 订阅导入前的三项合规与安全核查

在复制链接并粘贴进客户端之前，先花 10 秒确认三件事，可以避免绝大部分「以为软件坏了」的乌龙：

1. **确认品牌支持第三方通用订阅**：不是所有机场都提供 Clash 或 Shadowrocket 订阅。例如在站内档案中，[飞猫云](/brands/feimao/)、[隐形人](/brands/yinxingren/)、[SOGO 云](/brands/sogo/) 等均标注为仅支持专属客户端登录即用；而 [光速云](/brands/guangsuyun/)、[一翻云](/brands/yifan/)、[梯子云](/brands/tiziyun/) 等则支持第三方订阅导入。如果你用的是专属端品牌，后台根本不会给出通用订阅链接。
2. **复制对应的格式入口**：机场面板通常会区分「一键导入 Clash」「复制 Clash 订阅」「复制 V2Ray/通用 Base64 订阅」或「sing-box 订阅」。将 Base64 订阅填进仅支持原生 JSON 的 `SFA/SFI`，或把 Clash YAML 填进旧版仅认 Base64 的工具，都会解析失败。
3. **保护好现有可用配置**：如果是老用户更新订阅，切勿在未确认新订阅能正常拉取前先手动删除旧配置。理想做法是先「新建测试配置档案」验证拉取成功，再替换主力档案。

## 诊断决策树：从症状快速定位根因

当订阅拉取出现异常时，请顺着以下四条分支逐层排除，**每一步均为只读核查，不会破坏现有系统网络设置**：

```text
订阅导入或更新异常
 ├── 1. 客户端报错 TLS / SSL / 连接超时
 │      ├── 检查系统日期与时间是否偏差超过 1 分钟
 │      ├── 检查是否正开着「失效的旧代理」去拉取订阅（断开代理直连试一次）
 │      └── 确认订阅域名是否已更换（登录官网面板查看最新订阅地址）
 ├── 2. 返回 HTTP 403 / 404 / 401 / 502
 │      ├── 401 / 403：Token 失效、订阅被重置、或触发防爬虫/Cloudflare 盾拦截
 │      ├── 404：订阅路径错误或复制时漏掉末尾字符
 │      └── 502 / 503：机场面板后端临时维护或 API 网关过载
 ├── 3. 返回 HTTP 200 OK 但 0 字节（或节点数为 0）
 │      ├── 套餐已过期、未购买套餐或本月流量已归零
 │      ├── User-Agent (UA) 被后端过滤或未匹配到 Clash/v2rayN 标识
 │      └── 服务端仅返回了一条带到期提示的伪节点（信息节点）
 └── 4. 返回内容非空，但客户端报 YAML / JSON 语法解析错误
        ├── 机场订阅网址实际上返回了一段 HTML 登录/验证页面（如 Cloudflare 验证页）
        └── 把 Base64 文本直接当成 Clash YAML 解析，或客户端内核版本过老不支持新协议字段
```

## 场景一：HTTP 200 OK 但 0 字节（空白订阅）精准定位

「明明显示下载成功（`200 OK`），但文件大小 `0 B` 或者节点列表空空如也」是最让新手困惑的现象。背后常见有四种真实机制：

### 1. 服务端 User-Agent 识别与拦截

许多机场面板会根据 HTTP 请求的 `User-Agent` 字符串判断客户端类型：

- 请求头带 `Clash` 或 `clash-verge` 或 `mihomo`：返回 Clash YAML。
- 请求头带 `Shadowrocket`：返回适配小火箭的格式。
- 请求头带自定义浏览器 UA 或被安全规则拦截的未知 UA：部分面板会直接返回空内容（`Content-Length: 0`）或只回传基础头部信息。

**只读诊断方法**（在本地终端用 `curl` 查看响应头和前几行内容，注意将示例网址替换为你的订阅，切勿将真实带 Token 的订阅粘贴给任何在线网页工具）：

```bash
# 使用 Clash Verge/Mihomo 常见 UA 探测响应状态与字节数
curl -i -A "clash-verge/v2.0.0" "你的订阅URL" | head -n 25
```

观察输出结果：

- 如果 `HTTP/2 200` 且 `content-length: 0`，尝试切换成 `ClashMetaForAndroid`、`Shadowrocket` 或 `v2rayN` 作为 UA 再试一次。
- 在客户端内操作：在 Clash Verge Rev 的订阅设置（右键配置 — 编辑信息）中，找到 **User-Agent** 字段，显式填入 `clash-verge` 或 `Clash` 后重新更新。

### 2. 返回 HTML 验证页而非配置文件

如果上述 `curl` 输出的响应体开头出现 `<!DOCTYPE html>`、`<html` 或 `Just a moment...`，说明订阅域名套用了网页防爬盾（如 Cloudflare 质询），或者该 URL 本身是一个需要浏览器登录的网页入口而非 API 订阅地址。

**解决路径**：

- 登录机场用户面板，确认复制的是「订阅链接」而不是面板首页网址。
- 如果机场明确开启了订阅域名防恶意爬取盾，联系客服获取「免验证备用订阅域名」或开启客户端内针对该订阅的「通过代理更新（Use Proxy）」选项（前提是当前至少有一个节点还能连通）。

### 3. 套餐过期或流量耗尽导致下发空列表

不少面板在用户套餐到期或剩余流量为 `0` 时，不会返回 `403` 错误，而是依然返回 `200 OK`，但刻意清空所有可用节点（有时仅保留 1 条名为「套餐已过期，请续费」的无效节点，或直接返回 `proxies: []`）。

**核查方法**：查看响应头中是否带有 `subscription-userinfo` 字段，例如：

```text
subscription-userinfo: upload=123456; download=987654321; total=107374182400; expire=1798761600
```

其中 `expire` 为 Unix 时间戳，`upload + download` 对比 `total` 可直接看出流量是否已用尽。若已到期或耗尽，续费或重置流量后重新拉取即可。

## 场景二：TLS 证书错误与拉取环路排查

当客户端报错 `tls: failed to verify certificate`、`EOF` 或 `connection reset by peer` 时，按以下顺序无损排查：

1. **先断开当前代理再拉取**：新手最常踩的坑是旧节点已经全部失效，但客户端依然开着「系统代理」，或者在配置里勾选了「强制通过代理更新订阅」。此时客户端试图通过一个已经断网的节点去下载新订阅，必然触发连接重置或超时。**请先关闭系统代理与 TUN 开关，确保本地网络直连正常后再更新订阅**。
2. **核对本地设备时间**：如果电脑主板电池没电或虚拟机休眠恢复后系统时间退回过去几年，所有 HTTPS/TLS 订阅请求都会因证书不在有效期内而拒绝握手。校准操作参考 [时间漂移排查步骤](/guides/articles/time-drift-timeout-troubleshooting/)。
3. **测试订阅域名连通性**：在未开代理的终端里执行 `curl -I "你的订阅域名"`。如果直接超时或被重置，说明该订阅域名在当前本地网络环境下可能已被屏蔽，需登录机场最新可用发布页或联系工单获取备用订阅域名；不要在客户端中盲目勾选「跳过证书验证（skip-cert-verify）」作为长期方案。

## 场景三：订阅链接泄露风险与安全重置

你的订阅链接里通常包含唯一身份凭据（`token=...`）。**一旦订阅链接被泄露，任何人都可以直接导入你的全部节点并消耗你的付费流量**。

- **切勿使用来路不明的在线「订阅转换网页」**：把完整订阅 URL 粘贴进未知第三方网页转换，等价于把账号流量密钥拱手送人。若必须转换，尽量使用客户端内置转换（如 Hiddify、Karing）或自己本地部署的转换工具。
- **怀疑泄露时的止损动作**：第一时间登录机场网页后台，找到「重置订阅链接（Reset Subscription URL）」按钮并确认重置，使旧链接立即作废，随后在所有个人设备上重新导入新链接。

## 排查后仍无法解决的收集清单

如果完成上述所有只读诊断依然无法拉取订阅，向机场官方客服提交工单时，附带以下三项脱敏信息能大幅缩短处理时间：

1. 客户端名称、版本号与底层内核类型（例如 Clash Verge Rev / Mihomo）。
2. 脱敏后的报错信息截图（隐藏掉 URL 中的 `token=` 参数部分）。
3. 使用终端测试返回的 HTTP 状态码与 `content-type` 响应头（可确认是 `200 OK` 空响应还是 `403/502` 后端错误）。
