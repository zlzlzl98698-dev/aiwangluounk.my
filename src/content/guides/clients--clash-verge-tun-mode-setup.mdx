## 为什么普通系统代理无法满足重度用户需求？

大多数用户刚接触 Clash 时，使用的都是默认的“系统代理（System Proxy）”。系统代理的工作机制是向 Windows 或 macOS 的网络设置写入一个本地 HTTP/Socks5 端口（如 `127.0.0.1:7897`）。

然而，这种传统的系统代理存在致命的**盲区与缺陷**：
1. **对命令行终端无效**：Windows CMD、PowerShell、Linux WSL 以及 macOS Terminal 默认不会读取系统代理设置。你在终端里运行 `git clone`、`npm install`、`pip install` 或 `docker pull`，流量依然走本地裸连，频繁超时失败；
2. **对绝大多数网络游戏无效**：像《英雄联盟》外服、《Apex 英雄》、《CS2》等网络游戏使用原生 UDP Socket 发包，根本不走系统 HTTP 代理通道；
3. **特定桌面应用绕过**：诸如某些海外网银客户端、专有通信软件，会刻意规避系统代理以防拦截。

要彻底消除这些盲区，唯有开启 **TUN（虚拟网卡）模式**。

## 系统代理 vs TUN 模式技术架构全景对比

| 架构维度 | 传统系统代理（System Proxy） | 现代 TUN 模式（Network TUNnel） |
| :--- | :--- | :--- |
| **工作网络层级** | 应用层（Layer 7）及传输层端口（Layer 4） | **网络层（Layer 3，IP 层）** |
| **系统接管形态** | 修改操作系统 Internet 选项中的代理参数 | **在系统中虚拟出一张物理级虚拟网卡适配器** |
| **软件捕获范围** | 仅捕获遵循系统代理规范的浏览器与标准 App | **强制捕获整机 100% 进出网络流量（全协议全端口）** |
| **终端命令行支持** | 必须手动在终端执行 `export http_proxy=...` | **天然零配置支持终端命令秒速出境** |
| **外服网络游戏** | 无法加速任何不带代理设置的游戏 | **原生转发游戏 UDP 数据包，完美胜任网游加速** |
| **系统权限要求** | 普通用户权限即可开启 | **需要管理员权限安装底层网络服务驱动** |
| **DNS 劫持防御** | 易遭遇本地运营商 DNS 污染，需复杂配置 | **内核接管本地 53 端口，彻底免疫 DNS 泄漏与污染** |

## Clash Verge Rev 开启 TUN 模式标准三步作业法

请按照以下规范顺序操作，确保一次成功且不留系统网络隐患：

### 第一步：安装服务模式（Service Mode）

由于接管 IP 层需要高权限系统服务，必须先安装内核守护服务：
1. 打开 Clash Verge Rev，在左侧导航栏点击 **「设置（Settings）」**；
2. 在「应用设置」区域中，找到 **「服务模式（Service Mode）」** 项；
3. 点击右侧的 **「安装（Install）」** 或齿轮管理图标；
4. 操作系统会弹出 UAC 管理员提权窗口，点击 **「是 / 允许」**；
5. 安装成功后，服务模式右侧的状态灯将变为**绿色常亮**，表明后台驱动服务已就绪。

### 第二步：配置 DNS 栈与防泄漏参数

TUN 模式下最容易导致网络异常的是 DNS 冲突。建议在启用前，检查软件是否配置了合理的 Fake-IP 模式：
- 在「设置」中确保内核为 **Mihomo (Meta)**；
- 确保内部 DNS 开启，且运行模式为 `fake-ip`（这是 Mihomo 推荐的高性能分流模式，能在本地直接返回虚拟 IP，将真实域名解析交给海外节点落地端完成，既防污染又极大缩短握手耗时）。

### 第三步：激活 TUN 模式

1. 在左侧「设置」面板中，找到 **「TUN 模式（TUN Mode）」** 开关；
2. 将开关向右拨动开启，此时右侧状态图标点亮为绿色；
3. 在左侧底部，**关闭原有的「系统代理（System Proxy）」开关**（使系统仅受 TUN 网卡管理）；
4. 打开系统网络连接面板，你会看到新增了一张名为 `Meta` 或 `Mihomo` 的虚拟网络适配器，状态显示已连接。

## 局域网设备与私有网段放行（避坑指南）

开启 TUN 模式后，最常见的偶发问题是“打不开家庭路由器管理页（`192.168.1.1`）或连不上群晖 NAS”。
这是因为虚拟网卡将局域网流量误判为了外网数据。处理方式极其简单：

在你的订阅规则或全局扩展中，确保以下私有网段被明确标记为 `DIRECT`：

```yaml
rules:
  # 必须置于所有规则的最顶部，优先放行局域网
  - IP-CIDR, 192.168.0.0/16, DIRECT, no-resolve
  - IP-CIDR, 10.0.0.0/8, DIRECT, no-resolve
  - IP-CIDR, 172.16.0.0/12, DIRECT, no-resolve
  - IP-CIDR, 127.0.0.0/8, DIRECT, no-resolve
  - GEOIP, CN, DIRECT
  - MATCH, 节点选择
```

只要保留了上述前置规则，TUN 网卡在拦截到目标 IP 为局域网时便会毫秒级绕行本地直连，完全不影响局域网打印机、投屏与文件共享功能。
