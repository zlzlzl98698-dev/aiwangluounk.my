  - q: "为什么客户端节点测速只要 40ms，打开 Google 却提示 ERR_CONNECTION_RESET？"
    a: "因为客户端内置的「测速」通常只是向节点服务器发送了一个极小的心跳探测包（Ping 或握手测试），只要服务器端口开着，就能返回好看的毫秒数；但「打开网页」涉及到完整的浏览器请求：先查询 DNS 获取目标 IP，再通过代理向远端发起完整的 HTTPS 握手与大流量数据传输。如果节点后端的落地服务器与目标网站（如 Google）之间的国际路由阻断，或者出口 IP 遭到反爬封禁，就会出现「测速虽然绿，网页却打不开」的假活现象。"
  - q: "关闭代理软件后，电脑彻底断网连百度都上不去了，怎么一键恢复？"
    a: "这是因为很多代理软件在异常退出或强制关机时，没有来得及把 Windows 系统的代理设置还原。系统依然傻傻地把所有流量发给已经关闭的 `127.0.0.1:7897` 端口，导致全电脑断网。一键解决：打开 Windows 设置 -「网络和 Internet」-「代理」，找到「使用代理服务器」，手动将其开关拨到 **「关闭」**，或者重新打开 Clash Verge 勾选一次「系统代理」再正常右键退出软件，网络即可瞬间自愈。"
  - q: "在浏览器中提示「DNS_PROBE_FINISHED_NXDOMAIN」，该怎么处理？"
    a: "这属于纯正的 DNS 解析故障。在代理开启状态下，说明客户端内置的 DNS 转发模块卡死。尝试在 Clash Verge 设置中将 DNS 模式从 `redir-host` 切换为 `fake-ip`，或者将 Nameserver 备用服务器手动添加两组高质量公共 DNS（如 `8.8.8.8` 和 `1.1.1.1`）；并在 Windows 终端运行 `ipconfig /flushdns` 清空本地的陈旧 DNS 缓存。"

## 破除假象：测速绿色 ≠ 网页能开

很多用户看到客户端里每一个节点后面都标着绿色的小字（如 `42ms`、`58ms`），便坚信“代理绝对没问题，肯定是目标网站或者我电脑坏了”。

我们必须在技术层面上认清一个事实：**节点的延迟测试只是证明了你和代理服务器之间那条私有通道的握手正常，并不代表目标网站的完整数据能顺利送达你的浏览器**。

```
[浏览器发包] ──(环节一: 系统代理/TUN)──> [Clash 内核] ──(环节二: DNS 解析)──> [选定海外节点] ──(环节三: 节点到外网)──> [目标网站]
     ▲                                       ▲                                      ▲
     │                                       │                                      │
(高发故障点: 端口未接管)                (高发故障点: DNS 死锁)                 (高发故障点: 节点出口封禁)
```

只要上述三条链条中有任何一个节点断裂，你就会陷入“测速明明是绿色的，但就是打不开任何网页”的怪圈中。

## 典型报错代码与针对性自救对照表

| 浏览器屏幕报错 | 根本原因定位 | 针对性一键修复动作 |
| :--- | :--- | :--- |
| **ERR_PROXY_CONNECTION_FAILED** | 操作系统代理填写的端口与软件实际监听端口不匹配 | 核对系统代理设置中的端口是否与 Clash 混合端口一致 |
| **DNS_PROBE_FINISHED_NO_INTERNET** | 代理接管了 DNS 解析，但内置 DNS 上游服务器全部超时 | 客户端 DNS 切换至 Fake-IP 模式，刷新本地 DNS 缓存 |
| **ERR_CONNECTION_CLOSED / RESET** | 节点出口 IP 遭到目标平台（如 Google/CF）直接阻断 | 在客户端策略组中切换同大区的另一个备用节点 |
| **ERR_CERT_COMMON_NAME_INVALID** | 本地安全软件或公司网络实施了中间人 HTTPS 解密 | 关闭杀毒软件的“Web 网页防护”或信任代理证书 |
| **国内网站能上，所有国外网站打不开** | 策略组中选中的节点其实已经阵亡或欠费断流 | 点击策略组重新触发测速，改选可用的活跃节点 |

## 终极自愈排障四步法

遇到该故障时，按照以下步骤顺藤摸瓜：

### 第一步：检查 Windows 系统代理参数

1. 按键盘 `Win + I` 打开系统设置，进入「网络和 Internet」-「代理」；
2. 确认「使用代理服务器」开关处于**开启状态**；
3. 检查代理 IP 是否为 `127.0.0.1`，端口是否与你的客户端（如 Clash Verge 设定的 `7897`）**完全一致**。如果端口变成了 `1080`、`8080` 等其他数字，说明被其他软件篡改了，手动改回即可。

### 第二步：刷新本地 DNS 与重置网络套接字

打开 Windows 终端（PowerShell 或 CMD），依序粘贴并运行以下两条命令：

```powershell
ipconfig /flushdns
netsh int ip reset
```

第一条命令会彻底清除本地解析记录中的所有毒化结果，第二条命令能重置所有底层网络协议栈状态。

### 第三步：切换 Fake-IP 模式规避 DNS 污染

如果使用的是 Clash Verge Rev，在配置中强烈建议开启 **Fake-IP 模式**。
在 Fake-IP 模式下，客户端在收到浏览器的 DNS 请求时，不再向本地运营商或者缓慢的公网 DNS 发起漫长的查询，而是立即返回一个专有的内部保留虚假 IP（如 `198.18.0.x`）。
浏览器立即建立 TCP 连接，并将真实的域名封装在数据包内发给海外节点，由海外服务器在当地完成最终的高速域名解析。这种机制彻底绕过了本地 DNS 解析链，从物理上消除了 99% 的 DNS 污染与死锁。
