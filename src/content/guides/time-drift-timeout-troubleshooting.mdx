## 第一原则：先定界，再动手

「全节点超时（Timeout）」是代理使用中最让人焦虑的故障之一。但只要把问题切分成**「本地设备问题」「物理网络环境问题」「订阅与配额问题」「机场服务端问题」**四个象限，通常在 2 分钟内就能锁定真相。

请先用手机（关闭 Wi-Fi 走 5G/4G 流量）与电脑（同一 Wi-Fi）做一次交叉对比：

- **手机流量正常，电脑全超时**：100% 是电脑本地系统设置、时间漂移、防火墙或当前 Wi-Fi 路由器限制问题。
- **手机和电脑在同一个 Wi-Fi 下都全超时，手机切 5G 马上恢复**：当前宽带光猫、路由器或公司/校园网屏蔽了特定端口或中转入口，或本地路由器 DNS 异常。
- **手机 5G 和电脑宽带同时全超时，且确定订阅刚更新、时间准确**：才考虑机场节点大面积维护、入口变更或账号配额异常。

## 排错第一步：检查并校准系统时间漂移（最高频隐形杀手）

双系统（Windows + macOS/Linux）切换、虚拟机挂起恢复、台式机主板 CMOS 电池电量耗尽、或者手动改过系统日期后，本地系统时钟很容易偏离真实世界标准时间（UTC）数分钟甚至数小时。

### 为什么时间错了会全超时？

1. **VMess 协议硬性校验**：VMess 协议要求客户端与服务端的时间差通常不能超过 **90 秒**，超出误差服务端会直接拒绝数据包。
2. **TLS 1.3 与 Reality 握手校验**：Trojan、VLESS-Reality、Hysteria 2 等依赖严格的时间戳来验证证书有效期与防重放攻击，时间偏差过大时服务端或内核会直接中断连接。

### 各平台一键校准时间方法

不要肉眼看电脑右下角「大概差不多」就跳过，**60 秒以上的误差肉眼很难察觉，但足以搞挂全部节点**。

- **Windows（PowerShell 管理员运行）**：

```powershell
# 查看当前本地时间与系统时区
Get-Date
# 重启时间服务并强制与 NTP 服务器同步
net start w32time
w32tm /resync /force
```

若提示错误或无法自动同步，打开「设置」—「时间和语言」—「日期和时间」，确认开启「自动设置时间」，先点击一次「立即同步」（同步时间前务必先关闭故障代理客户端，否则同步请求本身也会走失效代理而失败！）。

- **macOS（终端查看与同步）**：

```bash
# 查看当前时间与时间服务器配置
date
sudo sntp -sS time.apple.com
```

也可打开「系统设置」—「通用」—「日期与时间」，开关一次「自动设置日期与时间」。

- **Linux / OpenWrt 软路由（极其容易发生时间漂移！）**：

很多无内置硬件时钟（RTC）的树莓派或迷你软路由重启断电后，系统时间会回退到固件编译日期，导致 OpenClash/PassWall2/Nikki 启动后全线超时。在终端执行：

```sh
date
# 若时间明显不对，检查或触发 ntpd / systemd-timesyncd 同步
ntpd -q -p pool.ntp.org
```

## 排错第二步：通过客户端日志关键词精确定位

打开客户端的「**日志（Logs）**」页面，将日志级别临时调为 `info` 或 `debug`，然后点一次任意节点的延迟测试或尝试打开网页，观察出现频率最高的一类报错文本：

| 日志报错关键词 | 真实技术含义 | 对应排查动作 |
| :--- | :--- | :--- |
| `i/o timeout` 或 `dial tcp ...: connectex: A connection attempt failed` | 数据包发出后在超时时间内未收到对端 TCP 握手回应 | 1. 核查本地是否真的能直连国内网；2. 更新订阅确认机场是否更换了中转入口 IP/端口；3. 检查电脑本地防火墙或杀软是否阻断核心进程出站 |
| `EOF` 或 `connection reset by peer` | 连接已触达目标或中间设备，但立刻被强制复位断开 | 1. 优先校准系统时间；2. 核对订阅是否过期或流量耗尽；3. 怀疑节点入口域名被运营商阻断（SNI 阻断） |
| `x509: certificate has expired` 或 `not yet valid` | 本地认为服务器 TLS 证书已过期或尚未生效 | **几乎 100% 是本地系统时间错误**，按第一步校准年月日与时区 |
| `listen tcp 127.0.0.1:7897: bind: address already in use` | 客户端想监听的本地代理端口已被其他程序抢占 | 检查是否同时运行了另一个代理软件、游戏加速器或抓包工具，关闭冲突软件或修改客户端混合端口 |
| `no such host` 或 `lookup ... failed` | 无法把节点域名解析成 IP 地址 | 检查客户端基础 DNS 配置（bootstrap/direct DNS）是否写死了一个无法访问的 DNS 地址，改用可用国内公共解析（如 `223.5.5.5`） |
| `permission denied`（常见于开启 TUN 时） | 代理核心没有获得创建或写入虚拟网卡的网络管理权限 | Windows 需安装服务模式或以管理员身份运行；macOS/Linux 需确认已正确授予网络扩展或 `CAP_NET_ADMIN` 权限 |

## 排错第三步：更新订阅与核查账户配额

很多用户反馈「昨天还好好的，今天一觉起来全 Timeout」，排除掉本地时间和端口占用后，最常见的原因是**机场中转入口 IP 进行了例行切换，或账号本身已触发停用条件**：

1. **先关闭代理再更新订阅**：在客户端关闭系统代理与 TUN 开关，点击订阅右侧的「更新」按钮。注意看更新时间是否刷新成功，而非报错或返回空内容。如果遇到 `200 OK` 但节点数为 0，立即转去查看 [订阅导入与 200 OK 空内容排查](/guides/articles/subscription-and-200ok-empty-fix/)。
2. **登录机场官网查看账户状态**：确认套餐是否刚好到期、本月流量是否已清零、或者是否因多设备并发超限（部分服务限制同时在线设备数）被临时挂起。同时查看官网公告栏是否有「某区线路割接维护通知」。
3. **测试多协议切换**：如果机场提供多协议（如 [一翻云](/brands/yifan/) 同时提供 Hysteria 2、VLESS-Reality 和 Shadowsocks），在个别校园网或企业网拦截 UDP（如 QUIC/Hysteria 2 端口）时，会出现 Hy2 全超时而 VLESS/Trojan 正常的情况。尝试在客户端内切换到 TCP 类的 VLESS/Trojan 节点进行交叉验证。

## 排错第四步：客户端无损安全重置步骤

如果确定时间准确、手机同网正常、订阅也是最新的，唯独当前这台电脑的客户端怎么都连不上（常见于升级客户端跨版本、配置覆写脚本出错、或系统休眠后虚拟网卡状态卡死），请按以下**保底而不丢数据的安全重置顺序**执行：

1. **导出或备份重要规则（无损前提）**：在重设前，先把自己的订阅 URL 妥善复制到本地安全记事本，如果有自定义覆写脚本也单独备份一份。
2. **彻底关闭并清理冲突状态**：
   - 在客户端内依次关闭 `TUN 模式` 和 `系统代理`。
   - 从系统托盘彻底退出客户端。
   - 检查任务管理器（Windows）或活动监视器（macOS），确认残留的 `mihomo`、`xray`、`sing-box` 后台进程已完全结束，避免「僵尸核心」霸占端口。
3. **重装或重启虚拟网卡服务**：
   - 若此前开启过服务模式（Service Mode），在客户端设置里点击「卸载服务」后再重新「安装服务」，可修复休眠造成的虚拟网卡句柄失效。
   - 清空客户端自带的规则集缓存与 Fake-IP 缓存（在配置文件目录删除 `cache.db`），防止损坏的本地路由缓存一直把流量指向旧节点。
4. **用「极简全新配置」隔离验证**：
   - 暂时关闭所有第三方合并/覆写脚本，新建一个空白测试档案直接重新导入原始订阅。
   - 如果裸订阅能通，说明问题出在你之前添加的自定义分流脚本或 DNS 配置里；如果裸订阅依然报错，结合日志信息联系机场客服排查账号或更换测试网络环境（如切到手机热点测一次）。
5. **警惕多客户端/加速器暗中抢占**：确认电脑后台没有自启网易 UU、雷神等游戏加速器、抓包工具（Charles/Fiddler/mitmproxy）或企业内网 VPN（EasyConnect/Sangfor/GlobalProtect）。这类工具会修改底层 LSP/WFP 驱动或系统路由表，排查代理问题前务必先彻底退出它们。
