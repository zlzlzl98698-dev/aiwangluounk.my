不管你使用的是 Windows 电脑、macOS 笔记本、Android 手机、iPhone 还是家里客厅的 OpenWrt 软路由，一次完整、规范的代理部署都遵循相同的六阶段逻辑闭环。建议先通览下表，再按步骤顺序推进：

| 阶段序号 | 阶段名称 | 核心任务动作 | 完成标志（通过标准） | 对应深入入口 |
| --- | --- | --- | --- | --- |

| **第 2 阶段** | **按生态选端** | 根据机场类型与终端系统选定对应内核客户端，核实下载渠道防仿冒 | 客户端安装完毕且可正常打开主界面，无内核报错或来源风险 | [客户端软件总览](/clients/) 与 [安装专题](/guides/install/) |
| **第 3 阶段** | **安全获取与导入** | 从官网面板复制合规订阅链接（严禁公共转换泄露 Token），或直接登录专属端 | 订阅更新后节点列表数量大于 0，到期日与剩余流量正常显示 | [订阅入门](/guides/subscription/) |

## 二、正式配置前必做的 5 项准备工作

跳过准备直接乱装软件，往往是后续 80% 莫名其妙报错的根源。动手下载客户端前，花两分钟依次核对以下 5 项条件：

1. **确认套餐状态与剩余可用流量**：登录你的服务商面板，确认当前订阅处于有效期内且剩余流量大于 0。如果刚完成续费或重置过套餐信息，记得后续需要重新拉取更新订阅，不能沿用过期链接。
2. **确认服务商的交付类型（通用订阅 vs 专属客户端）**：这是选端前最关键的分叉点。务必核实你购买的品牌是否提供 Clash / Base64 / sing-box 等通用订阅链接，还是已经全面转为仅限官方专属客户端登录即用。
3. **校准本机系统时间与时区（极高频隐形陷阱）**：打开操作系统设置的“自动设置时间与日期”以及自动时区同步。包括 VLESS、VMess 及各类 TLS 加密握手在内，服务端出于防重放攻击设计，**只要本地系统时间与标准时间漂移超过 60–90 秒，就会直接拒绝握手**，造成所有节点全部 Timeout 超时。
4. **卸载或退出冲突的网络接管软件**：在同一台设备上，切忌同时开启两款代理客户端、国内游戏加速器或公司远程 VPN（如 Cisco AnyConnect、OpenVPN 等），否则彼此抢占系统代理端口或虚拟网卡默认路由，必然引发断网或流量死循环。
5. **查看本机操作系统版本与 CPU 架构**：桌面端与移动端的压缩包后缀必须严格匹配机器硬件。常见对应关系为：主流 Intel/AMD 桌面 Windows 选 `x64`（极少数骁龙本为 `arm64`）；macOS 苹果 M1–M4 芯片选 `arm64` / `Apple Silicon`，老款 MacBook 选 `x64` / `Intel`；现代 Android 手机几乎均为 `arm64-v8a`；OpenWrt 软路由则须进路由器系统概览页核查具体 `Target Platform` 与防火墙版本（`fw3` 或 `fw4`）。

## 三、如何依据机场类型选择客户端：通用端 vs 专属端

站内 31 家品牌档案清晰揭示了当前服务商生态的两大阵营分化，直接决定了你接下来的操作路线（完整策略对比可参阅 [专属客户端 vs 通用订阅对比](/compare/dedicated-client-vs-universal-sub/)）：

### 阵营 A：支持通用订阅链接（开放生态）

- **档案代表品牌**：[光速云](/brands/guangsuyun/)（支持自研端及 Clash/Shadowrocket 第三方导入）、[一翻云](/brands/yifan/)（Hysteria 2 / VLESS-Reality / SS 三协议）、[梯子云](/brands/tiziyun/)（兼顾一键端与通用订阅）、[星岛梦](/brands/xingdaomeng/)、[二猫云](/brands/ermao/)、[唯兔云](/brands/weitu/)、[可信云](/brands/kexin/)、[速界](/brands/sujie/)，以及平价梯队的大佬云、闪电鼠等。
- **核心优势**：你可以自由选用开源社区维护的第三方客户端（Clash Verge Rev、v2rayN、FlClash、v2rayNG、Shadowrocket、OpenClash 等），不仅代码透明可控、无后台多余权限担忧，还能自由编写分流规则、挂载 OpenWrt 软路由、在多套客户端间无缝切换。
- **内核匹配注意**：如果服务商启用了较新的 **VLESS-Reality、Hysteria 2 或 AnyTLS** 等协议（例如一翻云的 Hysteria 2 或光速云 08-19 快照中的 AnyTLS），必须选用搭载 **Mihomo（Clash.Meta）、Xray 或 sing-box** 的现代客户端，早年停止更新的旧版原版 Clash（Clash for Windows 原版内核）无法识别这些新协议，导入后会直接报错或无法连接。

### 常见协议与订阅格式兼容性速查表

在选定客户端软件之前，可先对照机场面板标注的协议与订阅格式，确认目标软件是否原生支持，避免装好软件才发现打不开配置：

| 机场提供协议 / 订阅格式 | 推荐对应内核 | 推荐主流客户端 | 旧版软件常见冲突表现 |
| --- | --- | --- | --- |
| **Clash YAML（含 VLESS/Trojan/SS/Hy2）** | Mihomo (`Clash.Meta`) | Clash Verge Rev、FlClash、Stash、Clash Meta for Android、OpenClash | 已停更的原版 Clash 内核不识别 VLESS-Reality、Hysteria 2 与 AnyTLS，导入即报错 |
| **Xray 协议族（VLESS-Reality / VMess / Trojan）** | Xray-core 或 Mihomo | v2rayN、v2rayNG、Shadowrocket、PassWall2 | 老旧客户端缺少 Reality 公钥与 `uTLS` 指纹字段解析能力，导致握手超时 |
| **Hysteria 2（弱网抗丢包 UDP 协议）** | Mihomo、sing-box 或 Hysteria 原生 | Clash Verge Rev、FlClash、Hiddify、Karing、Shadowrocket、v2rayN | 不支持的旧版端会直接跳过该节点，或在测速列表里整行消失/全红 |
| **sing-box 原生 JSON 订阅** | sing-box | sing-box 官方端（SFA/SFI/SFM）、Hiddify、Karing、HomeProxy | 与 Clash YAML 格式完全不同，切勿把 JSON 文本直接强塞进只认 YAML 的旧客户端 |

### 阵营 B：仅支持官方专属客户端（封闭生态）

- **档案代表品牌**：飞猫云（[评测](/brands/feimao/)）、隐形人（[评测](/brands/yinxingren/)）、Firefly 萤火虫（[评测](/brands/firefly/)，2026 年 10 月起转向专属客户端）、SOGO 云（[评测](/brands/sogo/)）、闪跃（[评测](/brands/shanyue/)）、灵猫网络（[评测](/brands/lingmao/)）、全球云（[评测](/brands/quanqiu/)）以及无忧链接（[评测](/brands/wuyou/)，存在策略过渡记录冲突，购前需确认）。
- **核心特征**：官方后台**不提供第三方订阅 URL**，用户只能在官网下载专属安装包，输入注册账号密码一键登录使用。
- **操作边界与取舍**：这类方案对完全不想理解 YAML 规则的新手门槛最低，但也带来三个硬性约束——无法导入开源 Clash/Shadowrocket、通常无法自定义精细规则分流、且极度依赖官方是否提供你手头全部设备的专属客户端（例如有没有 Linux 版本或软路由方案，购买前需向客服核对，切忌轻信未经验证的笼统宣称）。同时，出于隐私与安全审慎原则，安装任何闭源专属客户端前请务必核实官方来源渠道，避免盲目赋予过高的系统全局权限。

## 四、分平台配置主线概览（精准直达各系统三级详文）

针对支持通用订阅的主流系统，以下梳理每条操作主线的核心软件选择、安装红线与首次配置重点；点击每节末尾的专属链接，即可进入已经写好的对应系统三级深度实战教程。

### 1. Windows 配置主线

Windows 是桌面端生态最丰富但也最容易误下第三方打包软件的平台。主流开源主力可分为两条技术路线：
- **Mihomo（Clash.Meta）规则生态**：首选 **[Clash Verge Rev](/clients/clash-verge-rev/)**（界面现代、支持配置覆写脚本与完善的 Service Mode 服务模式 TUN）或 **FlClash**（界面轻量、适合桌面与手机端维持统一体验）；对于历史资料中提到的 Mihomo Party，使用前须核实其当前仓库维护活跃度。
- **Xray / sing-box 多核心生态**：经典 **[v2rayN](/clients/v2rayn/)** 支持在 Xray 与 sing-box 等多核心间切换，对单节点链接分享、VLESS-Reality 与多核心兼容极佳（下载时注意区分含核心完整包与仅主程序包）；**Hiddify** 与 **Karing** 则基于 `sing-box`，擅长自动识别多种订阅格式。
- **安装与启动要点**：优先安装便携免安装版（Portable）或官方 Release 安装器，核对压缩包 SHA-256 哈希值，切勿在搜索引擎竞价广告中下载不明“破解版/中文绿化版”。首次启动建议关闭开机自启测试妥当后再打开，遇 Windows Defender 误报内核文件时务必先追溯源仓库校验后再决定放行。
- **详细步骤直达**：请参阅 [Windows 代理客户端全矩阵选型与安装指南](/guides/articles/windows-clients-guide/)。

### 2. Android 配置主线

Android 端配置逻辑简洁，但对 APK 来源安全与国产系统后台保活要求极高：
- **主力推荐软件**：偏好轻量单节点列表与 Xray 协议兼容选 **v2rayNG**；偏好 Clash YAML 规则分流与统一视觉选 **FlClash** 或 **Clash Meta for Android**；基于 sing-box 多格式自动适配可选 **Hiddify / Karing**。
- **两项高危避坑警告**：第一，安装 APK 前核对设备架构（现代安卓机多为 `arm64-v8a`，部分旧机或平板为 `armeabi-v7a`）；第二，**NekoBox for Android 在 Google Play 商店存在已被第三方控制的同名仿冒应用风险**，且该项目本身维护资源有限，普通用户请从可信开源仓库核验签名安装或优先选择 v2rayNG / FlClash。
- **国产 ROM 后台保活要点**：华为、小米、OPPO、vivo 等国产系统默认的智能省电与内存清理机制极易在锁屏数分钟后杀掉代理 VPN 进程，导致断网。配置完成后务必进入系统电池设置将客户端设为“无限制/允许后台高耗电”，并在多任务界面给应用卡片加锁。
- **详细步骤直达**：请参阅 [Android 客户端选型、APK 架构识别与仿冒风险警示](/guides/articles/android-clients-guide/) 与 [安卓 VPN 安全核验](/vpn/android/)。

### 3. iPhone / iPad（iOS/iPadOS）配置主线

受限于苹果沙盒与商店地区政策，中国区 App Store 已下架主流第三方规则代理工具，配置时须特别注重账号与支付安全：
- **主流客户端定位**：
  - **[Shadowrocket（小火箭）](/clients/shadowrocket/)**：外区商店付费买断应用，自研多协议内核，几乎兼容市面上所有常见协议与订阅格式，自带基础连通性测速与请求日志，是 iOS 端综合适配度最高的工具。
  - **Stash**：外区付费应用，内置 Clash 规则兼容引擎，最适合在电脑上已经习惯 Clash YAML 策略组与覆写逻辑的跨设备用户。
  - **Quantumult X（圈 X）与 Surge 5**：前者主打自定义脚本重写，后者面向重度网络抓包调试（内购订阅价格门槛较高），注意若机场仅提供 Clash 格式订阅，导入 Quantumult X 常需额外适配规则；此外 **Karing** 与 **Clash Mi** 在外区商店亦可作为 `sing-box` / `Mihomo` 生态备选。
- **外区买断安全铁律**：严禁在手机“设置”顶部的 iCloud 账户处登录网络上租借或免费共享的 Apple ID，避免触发查找我的 iPhone 远程锁机风险。务必使用自己独立注册的外区账号，仅在 **App Store 应用商店内**切换登录并完成正版付费买断（具体售价以所在区商店实时显示为准）。
- **详细步骤直达**：请参阅 [iOS/iPadOS 与 macOS 代理客户端全攻略](/guides/articles/ios-macos-clients-guide/)。

### 4. macOS 配置主线

macOS 虽然与 iOS 同属苹果生态，但在客户端分发渠道和底层网络授权上更接近桌面操作系统：
- **芯片架构严格区分**：Apple Silicon（M1 / M2 / M3 / M4 系列）必须下载 `arm64` / `aarch64` / `apple-silicon` 后缀版本，Intel 旧款机型必须下载 `x64` / `amd64` 版本（部分应用提供通用 `universal` 包）。混装虽然偶尔能借 Rosetta 2 转译运行，但会导致内核性能下降且可能引发授权组件异常。
- **主力客户端**：开源桌面端首选 **Clash Verge Rev**、**FlClash**、**v2rayN（macOS 版）**、**Hiddify**；偏好原生苹果生态调试界面且预算充足者可评估 **Surge Mac** 或 Stash 桌面生态。
- **未公证应用放行与服务授权**：开源免费软件常因未购买苹果付费开发者公证，双击时提示“无法验证开发者”或“已移至废纸篓”。确认是从官方正规渠道校验下载后，可通过“系统设置 → 隐私与安全性”点击“仍要打开”放行（不要全局关闭系统 Gatekeeper）。此外，开启增强模式（TUN）时会弹出管理员密码框请求安装辅助工具（Helper Tool）或批准系统网络扩展，属于创建虚拟网卡的正常权限。
- **详细步骤直达**：请参阅 [iOS/iPadOS 与 macOS 代理客户端全攻略](/guides/articles/ios-macos-clients-guide/)。

### 5. Linux 与 OpenWrt 软路由配置概览

- **Linux 桌面与无桌面服务器**：桌面发行版（Ubuntu/Debian/Fedora/Arch）通常由 Clash Verge Rev、FlClash、v2rayN 提供 `.deb`、`.rpm` 或 `.AppImage` 包；对于纯命令行服务器、树莓派或需要网页控制台的无桌面网关，推荐部署 **v2rayA**（提供 Web UI 面板与透明代理）。开启 TUN 时可通过授予核心二进制 `CAP_NET_ADMIN` 能力实现免 root 运行。
- **OpenWrt 软路由四大插件格局**：
  - **OpenClash**：基于 Mihomo 内核，图形化配置最全、规则社区生态最成熟，但组件较多、对小闪存路由器负担略大。
  - **PassWall2**：支持 Xray 与 sing-box 双核心切换，节点分流灵活，适合习惯 Xray 架构的路由用户。
  - **Nikki**：轻量化 Mihomo 透明代理新秀，**存在一条硬性固件版本红线——要求 OpenWrt 24.10 及以上版本，旧版固件不兼容**。
  - **HomeProxy**：基于 `sing-box` 的现代 OpenWrt 代理插件，依赖较新的 `nftables` 防火墙与官方软件源。
- **软路由部署前硬性自检**：动手指点安装前，必须先核对路由器的 **CPU 架构**、**可用剩余 Flash 存储空间**、以及 **防火墙框架（`fw3/iptables` 还是 `fw4/nftables`）**，并在修改任何网络配置前导出固件备份，预防局域网断联锁死。
- **详细步骤直达**：请参阅 [Linux 与 OpenWrt 软路由客户端实战指南](/guides/articles/linux-openwrt-clients-guide/)。

### 6. 各平台首次启动权限弹窗处置与安全边界对照

初次打开代理客户端时，操作系统往往会弹出网络安全或权限确认提示。区分“正常功能所需权限”与“异常可疑索权”，能帮你在保障安全的前提下顺利完成首次部署：

| 平台场景 | 正常弹窗提示内容 | 正确处置方式 | 需要警惕的异常信号（应立即中止） |
| --- | --- | --- | --- |
| **Windows 防火墙** | 询问是否允许 `mihomo` / `xray` / `Clash Verge` 访问“专用网络/公用网络” | 仅在信任的家庭或办公网络勾选允许访问，公共 Wi-Fi 下注意关闭 `allow-lan` 局域网共享 | 安装包要求彻底关闭 Windows Defender 实时防护才提供解压密码 |
| **Android 本地 VPN 请求** | 提示“应用请求建立 VPN 连接，用于拦截监控网络流量”，顶部随后出现钥匙图标 | 这是安卓系统允许第三方应用接管路由的标准接口，确认软件来自可信开源仓库后点击确定 | 非官方应用额外索要通讯录、短信、无障碍辅助权限或悬浮窗后台权限 |
| **macOS 辅助工具与安全放行** | 首次开 TUN 请求输入密码安装 Helper Tool，或提示开源程序“无法验证开发者” | 核对官方来源后在“系统设置 → 隐私与安全性”点击仍要打开；不要在终端执行关闭全局 Gatekeeper 命令 | 来路不明的破解工具要求反复输入密码却无任何清晰权限说明 |
| **Linux 服务与能力授权** | 启用虚拟网卡或透明代理时提示权限不足（Permission Denied） | 按标准文档授予内核二进制 `CAP_NET_ADMIN` 网络管理能力或使用 `systemd` 受控运行 | 来路不明的一键脚本直接下载未知闭源二进制并赋予全局 `root` 长期常驻 |

## 五、订阅链接获取与安全导入步骤

对于支持第三方客户端的开放型机场，导入订阅是连接服务的第一道操作关。按照以下规范执行，能直接避开 90% 的导入失败与泄露事故：

### 1. 准确识别“订阅 URL”与“官网/推广 URL”

新手最常犯的错误是直接把浏览器地址栏的机场官网登录页网址（甚至带 `aff` 邀请码的注册链接）粘贴进客户端的订阅输入框。真正的订阅链接通常位于服务商后台首页的**“一键订阅”或“导入订阅”卡片**中，点击“复制订阅地址”获得，其典型特征是 URL 路径带有 `subscribe`、`api/v1/client/subscribe` 或一长串随机 `token=` 参数。

### 2. 一键导入 vs 手动复制粘贴导入

- **一键导入**：在浏览器点击面板上的“一键导入到 Clash / Shadowrocket”，会唤起系统关联协议跳转并自动拉取配置。如果浏览器拦截弹窗或电脑上装了多款 Clash 系软件导致唤起错乱，建议改用手动复制。
- **手动粘贴导入（推荐）**：在面板复制对应的订阅地址（用 Clash Verge Rev / FlClash / Stash 就复制 Clash 格式，用 v2rayNG / v2rayN 就复制通用 Base64 或对应格式），打开客户端进入“订阅 / Profiles”栏目，粘贴 URL 并点击“导入/更新”。看到列表出现对应套餐名、剩余流量与到期日且可用节点数大于 0，即代表导入成功。

### 3. 严禁使用公共在线订阅转换（Token 安全红线）

当你手头只有 Base64 订阅而客户端需要 Clash YAML，或者反之时，绝对不要在搜索引擎里随便找一个免费的公共“在线订阅转换网站”把你的链接贴进去转换。订阅链接里的 `token` 等同于你账号的免密通行密钥，一旦发往陌生第三方服务器，对方即可获取你所有的节点配置并持续消耗你的套餐流量。

安全替代方案是：**优先向机场后台确认是否原生提供多种格式输出**；或者使用 **Karing / Hiddify** 这类客户端内置的本地转换引擎，以及自己在本地电脑运行开源转换工具，确保订阅 URL 永远不离开个人设备。如果你已经把订阅链接发到过公共群截图未打码或贴给过陌生转换站，请立刻登录机场面板点击**“重置订阅链接（Reset Token）”**，并在客户端重新导入新链接。

如果导入过程中遇到 `HTTP 200 OK 但 0 字节`、UA 拦截或 TLS 证书拉取错误，请直接对照排障详文 [订阅导入规范与 200 OK 空内容、UA 拦截、TLS 异常排查指南](/guides/articles/subscription-and-200ok-empty-fix/)。

## 六、Rule、Global、Direct 三模式本质区别与系统代理清理

成功导入节点后，所有主流规则客户端顶部或首页都会出现三个核心运行模式开关。理解它们的本质差异，能帮你省下大量流量并避免国内网银/社交软件卡顿。

| 运行模式 | 流量路由逻辑 | 适用场景 | 长期误用风险 |
| --- | --- | --- | --- |
| **`Rule`（规则模式）** | 由客户端内建分流规则表逐条匹配：国内域名/IP 走 `DIRECT` 直连，海外及 AI/流媒体域名走选定代理节点 | **95% 的日常办公、开发、追剧与 AI 使用默认标准模式** | 若规则集长期未更新或匹配漏网，少数冷门新域名可能走错路径 |
| **`Global`（全局模式）** | 忽略绝大多数分流规则，几乎所有符合拦截条件的对外请求一律强行塞入 `GLOBAL` 策略组走海外代理 | **仅用于临时故障排查**（测试某个网站打不开是不是因为分流规则误判直连） | **严禁长期开启**：淘宝、微信传图、国内网盘和 B 站视频全部绕海外再回国，延迟极高且迅速跑光代理流量配额 |
| **`Direct`（直连模式）** | 所有流量直接通过本地宽带出口直连目标站，不经任何海外代理节点（仅作为本地代理端口旁路） | 需要临时纯直连对比测速，或排查特定软件故障而不退出客户端窗口 | 无法访问任何受限海外资源 |

### 系统代理（System Proxy）的工作边界与退出清理

在 `Rule` 模式下开启“系统代理”开关，客户端所做的事其实是向操作系统的网络设置里写入一个本地监听地址（例如 `127.0.0.1:7897` 或 `10808`）。
- **哪些软件认系统代理**：Chrome、Edge、Firefox（需设为使用系统代理）、Safari 以及大部分常规桌面浏览器。
- **哪些软件不认系统代理**：Windows 命令行终端（CMD / PowerShell / Git Bash）、Python / Node 包管理器、`curl`、部分游戏客户端、微软商店 UWP 应用以及 Docker / WSL2 内部环境。
- **退出清理习惯**：规范关闭 Clash Verge Rev 或 v2rayN 时，软件会自动清除系统的本地代理地址；但如果遇到软件意外闪退、系统强制关机或任务管理器强杀进程，系统代理端口仍可能残留在操作系统设置里，导致电脑重启后虽然没开代理软件，浏览器却提示“无法连接到代理服务器”而全部断网。遇到这种情况，只需打开系统“网络和 Internet → 代理”，关闭手动代理服务器开关，或重新正常打开再正常退出一次客户端即可无损恢复。

## 七、TUN 虚拟网卡模式与服务权限管理

当你发现浏览器能正常访问海外，但终端里的 `git clone`、`pip install`、`claude` CLI 命令行或桌面端软件依然超时报错时，就到了启用 **TUN（虚拟网卡）模式**的时候。

### 1. 工作层级与权限门槛

系统代理属于“应用层礼貌性通知”，软件不读配置就不管用；而 **TUN 模式会在操作系统网络协议栈底层创建一张虚拟网卡（如 `Meta`、`utun` 或 `sing-tun`），通过修改系统路由表接管几乎所有应用程序的 TCP 与 UDP 数据包**。

正因为要改动系统路由表和创建网卡驱动，TUN 模式在各平台上都有明确的权限门槛：
- **Windows**：必须在客户端内安装 **Service Mode（服务模式）**，或以管理员身份运行核心程序；常见内核栈建议优先选用 `mixed` 或 `system`。
- **macOS**：首次打开 TUN 时需输入本机密码授权安装 Helper 服务或允许系统网络扩展。
- **Linux**：可通过为内核程序赋予 `CAP_NET_ADMIN` 能力，避免每次以完整 root 权限运行图形界面。

### 2. 开发环境兼容与安全回退

开启 TUN 虽然省去了给终端逐个配环境变量的麻烦，但也更容易和开发者本地环境冲突——特别是 **Windows WSL2、Docker Desktop、以及公司内网 VPN** 抢夺默认路由与子网网段（如 `198.18.0.0/16` Fake-IP 网段冲突）。因此日常如果只是刷网页和用网页版 AI，保留系统代理即可；确有命令行、容器或全局软件接管需求时再开启 TUN。一旦出现本地内网或 WSL 断网，先关闭客户端的 TUN 开关，虚拟网卡与临时路由通常会在数秒内自动销毁撤回。

关于系统代理与 TUN 栈的完整架构对照及 WSL2/Docker 兼容调整，请深入阅读三级文章 [系统代理 vs TUN 虚拟网卡：DNS 分流机制、开发容器兼容与安全回退](/guides/articles/tun-vs-system-proxy-dns/) 及二级专题 [TUN 模式原理解析](/guides/tun/)。

## 八、DNS 分流架构：`Fake-IP` vs `Redir-Host` 与浏览器 DoH 冲突

很多用户遇到“开了代理之后国内网页慢半拍，或者明明开了 TUN 分流规则却好像没起作用”，90% 是因为没理顺 DNS（域名解析）链路。代理工具拿到一个网址后，不仅要转发流量，还必须先决定“这个域名究竟由国内 DNS 解析出直连 IP，还是交给代理远端去解析，以免本地 DNS 污染或泄漏”。

### 1. `Fake-IP` 与 `Redir-Host` 核心对比

| DNS 模式 | 工作机制原理 | 优点 | 缺点与兼容注意 |
| --- | --- | --- | --- |
| **`Fake-IP`（推荐默认）** | 收到本地 DNS 请求时，内核立即从保留网段（通常为 `198.18.0.1/16`）分配一个虚假内网 IP 秒回给应用，同时在内存记录“虚假 IP ↔ 真实域名”映射；随后数据包到达 TUN 或代理端口时，再还原出真实域名执行分流或远端解析 | **响应极快**（省去一轮真实 DNS 等待耗时）、从根本上杜绝国内 DNS 污染，在 TUN 模式下保证 `DOMAIN` 类规则 100% 精准命中 | 若部分软件（或测试脚本、P2P 程序）需要拿到真实公网 IP，可能识别异常；且若客户端异常崩溃未清理缓存，系统可能短期内还缓存着 `198.18.x.x` 假地址 |
| **`Redir-Host`** | 客户端向配置好的上游国内/海外 DNS 服务器发起真实域名查询，并将真实的公网 IP 返回给应用程序；同时利用本地嗅探（Sniffer）或映射反查维持域名分流 | 返回给本机的全部是真实 IP，与本地局域网调试、部分开发工具或网络诊断命令兼容性较好 | 首包解析受真实上游 DNS 耗时影响；如果国内分流规则或上游 DNS 没配好，容易发生国内网站被解析到海外 CDN 变慢，或海外域名在本地被污染 |

### 2. 必须排查的隐形杀手：浏览器内置 DoH（安全 DNS）冲突

现代 Chrome、Microsoft Edge 与 Firefox 浏览器常常默认开启了 **“使用安全 DNS（DNS over HTTPS / DoH）”**。开启后，浏览器会跳过电脑操作系统的 DNS 设置，直接通过 HTTPS 向浏览器指定的外部 DNS 服务器发起解析——这意味着**你的 Clash/Mihomo `dns` 模块根本收不到浏览器的域名查询请求**！

最终结果就是：`Fake-IP` 无法工作、依赖域名匹配的分流规则大面积失灵、网页首屏频繁转圈卡顿。解决方法很简单：打开浏览器设置 → 隐私与安全 → 安全 → 找到“使用安全 DNS”，**将其关闭，或切换为“使用当前服务提供商/系统默认”**（由本地代理客户端统一接管 DNS 分流）。详细配置对照同样收录在 [系统代理 vs TUN 虚拟网卡：DNS 分流机制、开发容器兼容与安全回退](/guides/articles/tun-vs-system-proxy-dns/) 与 [DNS 错误排查页](/troubleshooting/dns/) 中。

## 九、规则分流写法核心逻辑：置顶直连、AI 分组与 `MATCH` 兜底

在 `Rule` 模式下，客户端的规则列表（`rules`）严格遵循**“自上而下，命中第一条即停止并执行”**的顺序原则。切记两条黄金铁律：第一，**永远不要直接修改导入后由机场自动更新覆写的原配置文件，而应在客户端“覆写（Override / Merge）”功能里追加个人规则**；第二，规则顺序必须保证“精细例外置顶、大类规则居中、兜底规则垫底”。

一套成熟实用的标准分流层级结构如下（可直接对应到 Clash/Mihomo 覆写逻辑中）：

```yaml
# 标准分流优先级结构示意（自上而下依次匹配）
# 1. 第一层：本地局域网、公司内网与绝对直连例外置顶
#    例如：192.168.0.0/16、10.0.0.0/8、企业办公域名、BT/网盘进程名 -> DIRECT
# 2. 第二层：AI 生产力专用分组（避开香港节点，固定指派日/新/美节点）
#    例如：OpenAI / ChatGPT、Anthropic / Claude -> 选择「日本/美国固定组」
#    例如：Google Gemini 相关域名 -> 选择「新加坡或已实测绿标组」
# 3. 第三层：流媒体与跨区敏感平台分组（防 TikTok 黑屏与 YouTube 送中）
#    例如：TikTok 域名 -> 指向「美/日/新已解锁节点」
#    例如：Netflix / Disney+ / YouTube -> 按区指派非送中节点
# 4. 第四层：常规海外高频开发与常用站点 -> 指向「香港低延迟主力组」
# 5. 第五层：国内主流域名与 IP 段规则集（GEOSITE,CN / GEOIP,CN） -> DIRECT
# 6. 第六层：全局唯一兜底规则（必须放在最后一行！）
#    MATCH, 🚀 常规代理（或你的默认策略组）
```

### 策略组（Proxy Groups）四种模式选择边界

写好分流规则只是把流量分到了不同的“池子”，真正决定池子里挑哪一个具体节点的，是策略组类型。日常配置时建议遵守以下选用原则：

| 策略组类型 | 节点挑选逻辑 | 推荐适用场景 | 禁用或避坑场景 |
| --- | --- | --- | --- |
| **`select`（手动选择）** | 由用户点击固定某一个特定节点长期使用 | **AI 生产力组（ChatGPT/Claude/Gemini）、高敏感账号登录、已测出的固定优质入口** | 无明显缺点，是最稳妥、可预测性最高的主力选择方式 |
| **`url-test`（自动测速选优）** | 定时向指定测试地址测速，自动切换到延迟最低的节点 | 日常通用海外网页浏览、常规视频流缓冲（建议将容忍差值 `tolerance` 设为 `80–120ms`） | 不适合对 IP 稳定性要求极高的银行或 AI 对话分组，测速阈值过小会导致频繁跳线断流 |
| **`fallback`（故障转移）** | 固定优先使用列表第一个可用节点，仅当主节点完全超时失效时才顺延切换第二个 | 兼顾“默认固定 IP 不乱跳”与“单节点宕机自动保底”的办公与开发组 | 需合理排序备用节点，把低延迟优质节点放在列表前两位 |
| **`load-balance`（负载均衡）** | 把并发请求按策略分散轮流交给多个不同节点同时转发 | 仅适合大文件多连接并行拉取或完全无会话状态要求的公开抓取场景 | **日常严禁用于 ChatGPT、Claude、网银或购物站**，多出口 IP 跳变极易直接触发风控锁号 |

### 三条高频避坑细节

1. **禁止把 `MATCH` 放顶部或中间**：一旦 `MATCH` 出现在上方，写在它后面的所有精细分流规则全部形同虚设，再也不会被执行到。
2. **AI 账号严禁配合 `load-balance`（负载均衡）策略组**：不要为了追求所谓“自动多线并发”而把 ChatGPT 或 Claude 放进会轮询不同出口 IP 的负载均衡组里。AI 平台对同一个对话会话中途跳变国家或 IP 极为敏感，极易立即触发风控退登。务必使用 `select`（手动固定选定单节点）或低频仅故障切换的 `fallback`。
3. **改完规则必须手动断开旧连接**：由于浏览器和客户端维持着 TCP/QUIC 长连接复用，修改完规则或切完策略组节点后，进入客户端的“连接（Connections）”面板点击“关闭全部连接”，新规则才会对下一秒的新请求生效。

想直接套用针对 ChatGPT 仅 APP(HK)、Gemini 分区限制、YouTube 送中（CN）与 Netflix 跨区的完整覆写策略，请跳转实战详文 [AI 与流媒体分流实战：破解 ChatGPT HK 限制、Gemini 失败、YouTube 送中与 Netflix 分区](/guides/articles/ai-streaming-geoip-routing/)，并结合 [Clash 配置指南](/guides/clash-config/) 与 [分流规则基础](/guides/routing-rules/) 理解语法细节。

## 十、订阅更新间隔设置、代理更新开关与多设备协同

### 1. 订阅更新间隔与“通过代理更新”开关

- **更新间隔**：建议把客户端的订阅自动更新周期设置为 **24 小时（1440 分钟）** 或仅在感到节点掉线时手动点击一次更新。在手机和电脑等多台设备上同时把刷新频率设成几分钟一次，不仅没有必要，还可能触发服务端 API 限流。
- **开启“通过代理更新订阅”**：国内网络环境下，部分服务商的旧订阅拉取域名偶发遭遇 DNS 污染或连接重置，导致“未连代理时更新订阅永远报错，连着其他可用节点却秒更新”。在 Clash Verge Rev 或 v2rayN 的订阅设置项中，勾选“允许通过代理更新（Use Proxy）”可以在至少有一个节点可用时保障后续无感更新；如果全部节点已不可用且拉不到新订阅，可临时切换手机热点拉取或前往官网查看最新备用订阅域名。

### 2. 多设备并发与软路由协同原则

站内档案中如光速云、星岛梦、二猫云、无忧链接、唯兔云、Firefly、U1S1、灵猫等均标注支持**“不限设备数量”**，但真实使用中仍需把握三项边界（详见 [跨设备使用指南](/guides/multi-device/)）：

1. **家庭协同的公平使用边界**：“不限设备”意味着你名下的工作电脑、家用台式机、手机、平板和客厅软路由同时挂在自家网络下使用完全合规；但不要把同一个订阅链接公开发给多名外地朋友一起重度下载，不同省市 IP 高并发拉流容易触发服务端异常审计。
2. **居家软路由 + 出门移动客户端组合**：如果在家里部署了 OpenWrt 旁路由或主路由（如 OpenClash / PassWall2 / Nikki），家庭局域网内的电视盒子与电脑无需再单独开桌面客户端；但笔记本带去公司或手机外出切换到 4G/5G 时，仍需开启本机客户端，同时注意手机回到家连上已经开着代理的软路由 Wi-Fi 时，**记得关闭手机本机代理，避免手机和软路由形成双层代理嵌套**。
3. **控制多端后台同步与自动测速消耗**：如果家中四五台设备全天候挂着每 5 分钟一次的 `url-test` 全节点测速，且每台电脑的网盘同步、系统更新都未正确配置直连规则，后台静默消耗的套餐流量会超出预期。
4. **局域网共享（`allow-lan`）与公共 Wi-Fi 安全边界**：电脑端客户端通常提供“允许局域网连接”开关，方便在宿舍或家里临时让同一 Wi-Fi 下的手机、Switch 游戏机或电视通过填入电脑内网 IP 与端口共享代理。但在咖啡厅、机场、酒店等公共 Wi-Fi 环境下，务必关闭 `allow-lan`，或者在配置文件中开启 HTTP/SOCKS 用户名密码鉴权，防止同局域网陌生设备扫描端口并白嫖你的套餐流量。
5. **切换软件或卸载客户端前的无损清理清单**：当你打算更换一款客户端（例如从 v2rayN 迁移到 Clash Verge Rev）或彻底卸载时，建议按三步收尾：第一，先在原客户端界面内关闭“TUN 模式”与“系统代理”开关，并取消“开机自启”；第二，把个人整理好的覆写脚本或规则模板导出备份到本地文件夹（切勿把含个人订阅 Token 的文件上传到公开网盘或公开代码仓库）；第三，正常退出原客户端后再安装新工具，确保端口与虚拟网卡干干净净，不留历史冲突隐患。

## 十一、配置完成后：三步验证配置是否真正生效

很多人以为点击了“开启代理”开关就算大功告成，实际上可能根本没接管成功，或者全部流量正以全球绕路的方式狂烧流量。完成配置后，花 3 分钟走完以下三步验证闭环：

1. **第一步：检查客户端“连接（Connections）”实时日志**
   保持客户端在 `Rule` 模式开启状态，打开浏览器先后访问一个国内网站（如百度或淘宝）和一个海外网站（如 YouTube 或 ChatGPT）。切回客户端的“连接 / 请求日志”面板，确认两项事实：国内网站命中的规则列显示为 **`DIRECT`**；海外网站命中的规则列显示为你设定的**目标策略组名称及具体海外节点名**，且有正常的上下行字节数字跳动。
2. **第二步：核对地区出口与端到端业务连通性**
   分别测试核心业务目标：打开 GitHub / YouTube 确认响应流畅且 YouTube 左上角地区显示正常（如 HK/JP/US，未意外变成 CN 送中）；打开网页版 ChatGPT、Claude 或 Gemini 确认实际走的节点与你预期的 AI 策略组一致且能正常发起对话。
3. **第三步：用 100MB 下载做吞吐与 1x 倍率账单核对**
   在正式大流量使用前，先登录机场官网记下当前剩余流量数值，暂停其他下载软件，单选常用主力节点完成约 100MB 的正常海外资源加载或测试下载；几分钟后刷新官网面板，确认扣减流量大致等于 100MB（若使用了 2x 倍率节点会扣除约 200MB），同时在本地晚高峰 20:00–23:00 观察单线程加载速度是否满足日常追剧或办公要求。

### 附：日常省流习惯与月度配额核对建议

很多用户明明购入了每月 100GB–150GB 的主流套餐（如 19–25 元月付档），却不到半个月就耗尽配额，往往并非日常刷网页用掉的，而是以下四类后台大户悄悄走代理所致：
- **系统大型更新与游戏平台下载**：Windows Update、macOS 系统升级包、Steam/Epic 游戏客户端下载动辄数十 GB，应确认其域名或进程在 `Rule` 模式下命中 `DIRECT`（如国内 CDN 节点），避免白白消耗海外专线配额。
- **云盘同步与 P2P 上传工具**：Baidu Netdisk、阿里云盘、OneDrive 或 qBittorrent 等上传下载软件一旦走代理，因为面板按“上行 + 下行双向字节”计费，几小时即可跑空小流量年付包（例如 40–60GB/月轻量包）。建议直接在覆写规则中按进程名强制直连。
- **高码率 4K/8K 自动播放**：YouTube 在千兆网络下默认可能自动拉取最高 4K 60fps 码率（每小时约消耗 6–10GB），手机或平板小屏幕观看时手动锁定 1080p 即可省下 60% 以上流量。
- **核对面板流量重置日口径**：留意服务商是按“每月 1 号固定清零”还是按“购买日起每 30 天循环重置”，并在月付先试用验证期结束前预留数天观察账单统计是否准确，确保后续续费节奏心中有数。
- **善用客户端流量与连接监控复盘**：绝大多数现代客户端（如 Clash Verge Rev 的“连接”视图、Shadowrocket 的“流量/数据统计”）都能统计单月按域名或进程划分的累计消耗。如果发现某个不知名后台更新域名占据了前几名流量榜首，只需把它加入覆写规则置顶直连，就能立即堵住流量黑洞；同理，针对非长期有效的一次性流量包用户（例如 100GB–247GB 不过期备用包），更应在首次配置时就把大文件直连与 1x 倍率规则核对到位，防止一次性包在几天内被后台更新误耗一空。

## 十二、高频出错分流入口：按症状直接定位排障指南

配置或日常使用中一旦出现异常，**切忌盲目卸载重装、删除全部配置或随意用脚本重置系统网卡**。对照下表症状，直接点击进入对应的标准化排查决策树：

| 当前遇到的具体症状 | 最常见底层诱因 | 精准排障与恢复直达入口 |
| --- | --- | --- |
| **全部节点测速显示超时（Timeout），网页全红连不上** | 本地系统时间漂移超过 60–90 秒、套餐到期/未刷新订阅、本地 ISP/防火墙拦截 | [节点超时排查页](/troubleshooting/timeout/) 与 [节点全超时排错详文](/guides/articles/time-drift-timeout-troubleshooting/) |
| **导入订阅报错、返回 HTTP 200 OK 但 0 字节（空白节点）** | 贴错了官网登录 URL、UA 被拦截、订阅拉取域名遇 TLS/污染错误、或该机场其实仅限专属端 | [订阅失败排查页](/troubleshooting/subscription-failed/) 与 [订阅 200 OK 空内容排查详文](/guides/articles/subscription-and-200ok-empty-fix/) |
| **代理已开启但部分软件没走代理，或开启 TUN 后 WSL2/Docker 断网** | 系统代理仅对浏览器有效；开启 TUN 后与容器网段、企业 VPN 或混用系统代理冲突 | [TUN 与系统代理故障页](/troubleshooting/tun-proxy/) 与 [TUN vs 系统代理详文](/guides/articles/tun-vs-system-proxy-dns/) |
| **国内网页打开变慢、分流规则无效或局域网 NAS 连不上** | 浏览器开启了内置 DoH 安全 DNS 与代理抢解析、Fake-IP 网段冲突或 `Redir-Host` 异常 | [DNS 错误排查页](/troubleshooting/dns/) 与 [故障排查总览](/troubleshooting/) |
| **退出软件后全电脑彻底断网，或软件启动即崩溃闪退** | 异常退出未清理系统代理残留端口、Service Mode 权限不足、配置文件覆写语法写错 | [无法连接排查页](/troubleshooting/cannot-connect/) 与 [客户端无法启动排查页](/troubleshooting/app-startup/) |
| **节点绿灯能上 Google，但 ChatGPT 报错、Gemini 失败或 YouTube 送中** | 错把香港节点当 AI 主力（仅 APP 或屏蔽）、新加坡/台湾节点出现 YouTube `送中(CN)` 或负载均衡跳 IP | [AI 与流媒体分流详文](/guides/articles/ai-streaming-geoip-routing/) 与 [AI 与流媒体专题](/ai-media/) |

把上面六阶段路线与排障分流表收藏对照，无论你后续更换哪家服务商还是新添置了电脑、手机或软路由设备，都能在一刻钟内稳妥跑通全套加密代理与精细化分流环境。
